# AGENTS.md(作品 repo 用 初稿 v0.2)

> 会議室での下書き。確定後、雛形 repo `web-app-template` の AGENTS.md を置き換える。
> 方針: 「何を・なぜ」だけ書く。「どうやって」は書かない。長くしない(目安 60 行以内)。

## この repo は何か

- Mukkii の個人開発の作品 1 本。まずパイロット版(モック)を最短で公開するための repo。
- 企画は `SPEC.md`。読んでから始めろ。書いてあることが全て。書いてないことは自分で決めろ。
- ジャンル別の追加指示があれば `SPEC.md` の冒頭に「読め」と書いてある。なければ無い。

## 進め方(最重要)

1. **止まるな。** 伝えられたゴールまで、だめもとで作り切れ。途中で確認を取りに来るな。
2. **ゴールは改造の土台。** 「◯◯みたいなの」と言われたら、そっくりを仕上げるのではなく、人間がそこから改造できる状態まで作れ。
3. **質問は溜めろ。** 判断に迷ったら仮決めして進み、`QUESTIONS.md` に「何を仮決めしたか、他の選択肢は何か」を並べろ。人間は後でまとめて答える。
4. **複数案を求められたら** `variants/a`, `variants/b` … に並べ、それぞれ動く状態で置け。
5. **パイロットは製品ではない。** セキュリティ監査、網羅的テスト、設計文書の肥大化はするな。動いて公開できればよい。

## 技術の既定値

- Vite + TypeScript。2D は Phaser 3。3D は動きの激しいものは Babylon.js、見せるのが主なら Three.js。SPEC.md に指定があればそれに従え。同梱のエンジン層(`engine/`)を先に使え。
- 型で止まるな。動く方を優先しろ。
- ビルド出力は `dist/`。Vite の `base` は `./`(同じフォルダから読む設定。Pages でも itch.io でも同じ成果物が動く)。

## 素材

- 自作より外部素材を優先。クレジット不要のものを優先。
- 使った素材は全部 `ASSETS.md` に出典・ライセンス・(AI 生成なら)どの AI かを書け。書いてない素材は使うな。

## 公開

- `docs/PUBLISH.md` を日本語と英語で埋めてから公開ジョブを呼べ(タイトル、一言、説明、操作方法、スクショ)。
- 公開は `.github/workflows/build-and-deploy.yml` 1 本(main に push → ビルド → Pages、任意で itch.io)。ここを変える時は `QUESTIONS.md` に理由を書いてから変えろ。

## 文書と記録

- `SPEC.md` の挙動を変えたら `SPEC.md` を直せ。長くするな。
- 設計判断は `DECISIONS.md` に 3 行で追記。書き換え禁止。
- 汎用的に使える道具ができたら `mukkii-game/dev-tools` への提案として `QUESTIONS.md` に書け。

## 禁止

- テストを消す・スキップする。ライセンス不明の素材。秘密情報のコミット。
- 同じ作品 repo に同時に push する経路を 2 つ作る(サブエージェントや他セッションへの質問は自由。push する者は 1 つ)。

## ローカルコマンド

```
npm ci && npm run dev      # 開発
npm run build              # dist/ 生成
```
