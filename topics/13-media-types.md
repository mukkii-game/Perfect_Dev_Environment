# 13 作るものの種類: ゲーム・アプリ・漫画・動画

## 現状の結論

- **会議室は 1 つのまま。** ゲーム・アプリ・漫画・動画を同じ repo で扱う(2026-10-01 提案)。
  分けると AI・素材・宣伝のカタログが 2 箇所にでき、片方だけ更新されてズレる。
- **セッションは使い捨てでよい。** 記憶は repo(AGENTS.md・knowledge/・topics/)にある。
  漫画を深く詰める日は、この repo で新しいセッションを開けばそこから続く。
- **作品は 1 本 1 repo**(ゲームと同じ)。漫画 1 作、動画 1 シリーズにも repo を切る。
- 着手順: **アプリ(ほぼ今のまま)→ 動画(半分できている)→ 漫画(土台から作る)**。

## 何が共通で、何が違うか

| | ゲーム | アプリ | 漫画 | 動画 |
|---|---|---|---|---|
| **AI の使い分け**(`ai-models.md`) | 共通 | 共通 | 共通 | 共通 |
| **素材カタログ**(`catalog-tools.md`) | 共通 | 共通 | 絵の比重が大 | 音・絵の両方 |
| **宣伝・SNS**(`promotion.md`) | 共通 | 共通 | 共通 | 共通 |

| 雛形 | `web-app-template` | **同じ雛形でほぼ足りる** | **新しく要る** | 一部あり(下記) |
| 公開先 | Pages / itch.io / ポータル | Pages / ストア | pixiv / X / note / BOOTH 等 | YouTube / TikTok / X |

**共通の土台が 7 割、違うのは「作る工程」と「公開先」だけ。** だから会議室は分けない。

## 種類ごとの見立て

### アプリ
- ゲームとほぼ同じ。`web-app-template` から作れる(Web/JS、Pages 公開、公開キット)。
- 違いは中身だけ(ゲームループの代わりに画面と保存)。**新しい仕組みはほぼ要らない。**

### 動画
- **半分は既にある**: プレイ動画の自動収録(Playwright)、スクショ、ffmpeg での合成(`catalog-tools.md`)。
- 足りないもの: 台本 → 素材 → 編集 → 字幕 → 書き出し、の流れを 1 本の手順にすること。
  ショート動画(縦長・数十秒)の書き出し。公開先(YouTube / TikTok)への出し方。
- ゲームの宣伝動画と、動画そのものが作品の場合で、同じ道具を使い回せる。

### 漫画
- **土台から作る必要がある。** 今の仕組みに対応するものが無い。
- 工程: 企画 → 台本(ネーム)→ 絵 → コマ割り → 文字入れ → 公開。
- **最大の難所はキャラの一貫性**。AI 画像は 1 枚ごとに顔や服が変わる。ここを解かないと連載にならない。
  解き方の候補(未調査): キャラの基準画像を固定して参照させる機能、学習(LoRA 等)、
  人間が描いた線画に AI で塗る、3D モデル(VRoid 等)をポーズさせて下絵にする。
- 文字入れ・コマ割りはコードで自動化できる見込みが高い(**0 層にできる**)。
- 「ヘタウマ・手書き風は人間が描く」(06 の方針)が一番効く領域でもある。

## 検討中の論点

1. 着手順(アプリ → 動画 → 漫画)でよいか。漫画を先にしたい事情はあるか
2. 漫画の絵: AI 中心か、人間の線画 + AI 塗りか、3D 下絵か(試してから決める)
3. 動画は「ゲームの宣伝」が主か、「動画そのものが作品」か
4. 作品 repo の名前の付け方(種類が増えると一覧で区別が要る。接頭辞 `game-` `app-` `manga-` `video-` 等)
