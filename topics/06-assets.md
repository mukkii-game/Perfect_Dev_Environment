# 06 外部アセットの方針と索引

## 現状の結論

- AI 生成より外部入手が有利(品質・速度・トークン)なら外部を使う。
- 優先順: クレジット不要の無料 → クレジット要の無料 → 有料(時間短縮や品質差が大きい時)。
- 対象は絵、コード、ツール、音、エンジン、その他便利なもの全部。
- 手書き風のヘタウマ絵など、AI で伝わらないものは人間がレタッチ。

## 2026-09-13 追記(ユーザー意向と会議室の整理)

ユーザー意向: 海外の無料素材だけでなく、有料契約(Adobe)、日本発の配布素材(VRoid、効果音ラボ、魔王魂 など)、Unity Asset Store も駆使する。作品の内容で選び、判断がつかなければ早めに人間に聞く。

### 素材の入手先の階層(案)

| 層 | 例 | 使い方 |
|---|---|---|
| 無料・CC0・海外 | Kenney, Quaternius, KayKit, Poly Haven, ambientCG, Freesound(CC0 フィルタ), OpenGameArt | API・ミラーで AI が自動検索。第一候補 |
| 無料・日本発(規約あり) | 効果音ラボ, 魔王魂, 甘茶の音楽工房, DOVA-SYNDROME, いらすとや, ぴぽや, VRoid Studio / VRoid Hub, BOOTH の無料配布 | 規約が個別(クレジット要否、商用可否、改変可否、ゲーム同梱可否)。索引に規約を書いておき、AI は索引の範囲でだけ使う |
| 有料契約済み | Adobe Stock(契約プランで使える枠を確認)、Adobe Fonts、Firefly 生成 | Adobe Stock は「標準ライセンス」でゲーム同梱可だが、配布数・改変の条件を索引に明記 |
| 有料・都度購入 | Unity Asset Store, itch.io の有料パック, BOOTH の有料 | Unity Asset Store 素材は **Unity 以外での利用を規約が制限する場合がある**。Web ゲームに流用する前に規約確認 |
| AI 生成 | ChatGPT / Gemini の画像、Firefly、ローカル生成(下記) | 「トークンを大量に使って使えない絵」を避ける作法を 02 に書く(下記) |

### 判断ルール(AI 向け、AGENTS.md に載せる)
1. 索引にある素材を先に探す。海外 CC0 → 日本発(規約確認済み)→ 契約済み有料 の順。
2. 作品の雰囲気で海外 / 日本発を選ぶ(和風・日本語 UI・ヘタウマ系は日本発が合いやすい)。
3. 3 回探して合わなければ AI 生成、それでも合わなければ **人間に聞く**(QUESTIONS.md に「欲しい絵の説明 + 試した候補」を書く)。
4. 使った素材は出典・規約・クレジット文を CREDITS.md に必ず書く。

### AI 画像生成の作法(02 と共有)
- Claude から ChatGPT / Gemini の画像生成を呼ぶことは **可能だが、API 経由**。ChatGPT Plus / Gemini の月額契約には API は含まれない(別料金の従量課金。Gemini API には無料枠あり)。作法としては「Claude がプロンプトと仕様書(サイズ、枚数、スタイル、透過の要否)を書き、人間が ChatGPT / Gemini のチャットで生成して `assets/inbox/` に放り込む」が現状の最安。自動化するなら Gemini API の無料枠から。
- **ローカル生成**: RTX 4080 Super があるので、Hugging Face のオープンモデル(Stable Diffusion 系、FLUX 系)を ComfyUI 等で動かせば **枚数無制限・トークン消費ゼロ**。ドット絵・ヘタウマ風の LoRA も多い。09 の「GPU が要る作業」に該当。自宅 PC を付けっぱなしにしない方針とは要調整(生成だけ起動して回す)。
- **チャット UI をロボット操作して ChatGPT / Gemini に描かせる案(ユーザー質問 2026-09-13)**: 技術的には可能(Chrome 拡張の Claude、Playwright、Cowork の画面操作)。ただし (1) OpenAI・Google の利用規約は、消費者向けチャット画面へのプログラム的・自動的アクセスを禁じており、検知されるとアカウント停止の可能性がある(仕事でも使うアカウントなら致命的)、(2) UI 変更や CAPTCHA で壊れやすい、(3) PC を付けている必要がある。→ **全自動には使わない**。人間がボタンを押す「半自動」(Claude が仕様書を書き、拡張がフォームに貼り、人間が送信して結果を保存)は規約上グレーの低頻度利用に留める。
- 自動化の正攻法(優先順): ① ローカル生成(RTX 4080 Super + Hugging Face のモデル、規約問題なし、無料、無制限)、② Gemini API の無料枠(公式、自動化可)、③ OpenAI 画像 API の従量課金(1 枚数円〜十数円、公式、自動化可)、④ ChatGPT / Gemini のチャットは **人間が一発で高品質を狙う時だけ** 使う。
- 品質のコツ: 生成前に「参考画像 1 枚 + スタイル語 + 禁止事項」を固定した **スタイル定義ファイル**を作品ごとに置く。1 枚ずつ会話で直さない。

### ツール(Adobe / Blender)
- Blender: **AI から操作できる**(blender-mcp、MIT)。簡易モデル生成、glTF 書き出し、Poly Haven 連携。3D 作品の日に使う。
- Adobe: Photoshop / Illustrator は AI から直接操作する定番手段が薄い(スクリプト実行や Firefly API はあるが個人契約で使える範囲は要確認)。当面は **人間がレタッチする道具**として位置づけ、AI は「何をどう直すか」の指示書を書く。
- 判断がつかない時はユーザーの言葉どおり「早めに人間に聞く」。

### Hugging Face
- 無料でオープンモデル(画像生成、音声合成、音楽生成、小型 LLM)、データセット、デモ(Spaces)が使える。RTX 4080 Super ならローカルで画像生成・TTS・小型 LLM が現実的。用途: 画像の大量生成、効果音・BGM の生成(音楽モデル)、日英翻訳の下請け(トークン節約)。導入は 08(自動化)で「ローカル生成サーバー」として検討。

### ライセンスの用語(人間向けメモ)
- **MIT**: 「著作権表示を残せば、商用でも改変でも自由に使ってよい、保証はしない」という最も緩いオープンソースの許諾。**コード向け**。素材(絵・音)には通常使わない(素材は CC0 や CC BY)。
- 自分の無料ゲームに MIT を付けるか: **コードは MIT で公開してよい**(他人が学べる、Lv5「言語化」の実績になる)。ただし **絵・音・シナリオ・キャラは MIT にしない**(他人が丸ごと再配布できてしまう)。repo の LICENSE は「コードは MIT、assets/ は各素材の規約と自作分は All rights reserved」の 2 段書きにする。製品化したい作品は最初から非公開でもよい。

## 検討中の論点

1. 索引の置き場: スプシ(検索・フィルタしやすい)か md か。両方なら正本はどちらか
2. 索引の列: 名前、URL、種類、ライセンス、クレジット要否、商用可否、使った作品、保管場所(Drive)
3. AI が索引を自動検索できる形(→ 02 の「機械検索は ◯◯.py」)
4. ライセンスの記録を作品 repo の `ASSETS.md` に強制する仕組み
