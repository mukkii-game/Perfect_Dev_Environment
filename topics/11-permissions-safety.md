# 11 権限と安全(AI に何をどこまで許しているか)

## 現状の結論

- ユーザーの自己評価(2026-09-13): 「自動化のため人間チェックなしで全 OK にしたり、スプシ書き換えを許可したりしている。万が一仕事関係のフォルダを壊したら怖い。**今どこまで許可しているか把握していないし、把握する方法も十分でない**」。
- 方針: 自動化の度合いは下げない。代わりに **「壊れても困らない領域」と「絶対に触らせない領域」を物理的に分ける**。判断で守るのではなく、境界で守る。

## 2026-09-13 ユーザー回答(現状の権限)

- PC: **どこでも触れるように許可した記憶**。Git クローンは `E:\ゲーム企画\` 配下(最近)と `E:\` 直下(未整理多数)。E は最大容量のドライブ。モバイル PC は D。正本は GitHub なのでドライブ不統一は大問題ではない。
- Google Drive: デスクトップ版で `G:` としてマウントし、AI はそこを通して Drive を触れる。**社外(仕事)ドライブへのショートカットも G: に置いてあり、AI が直接触れる状態**。仕事データは 5TB Drive の中、全部 G: 配下。
- アカウント: 仕事も個人も同じ Google アカウント。分けることは可能だが未実施。
- ブラウザ: Chrome 拡張で Claude が直接操作。Codex は拡張なし。
- ユーザー自身の案: 「個人フォルダまでは自由、そこから社外ドライブへは人間の許可を得てから GAS や Python でコピー」という段階を踏む形。

### リスク評価(会議室の見立て)

| 対象 | 危険度 | 理由 |
|---|---|---|
| G: 経由の社外ドライブ | **最高** | 他社データ。AI の誤削除・誤上書きが他人に及ぶ。Drive の版履歴は 30 日で、共有ドライブは復旧に管理者が要ることも |
| G: 内の個人の仕事データ | 高 | 自分の仕事。版履歴で戻せるが、AI が大量に触ると気づきにくい |
| E: の未整理ローカル repo | 中 | GitHub に push 済みなら復旧可。未 push の物があれば失う |
| Chrome 拡張の Claude | 中 | ログイン済みサイト(仕事の SaaS 含む)を操作できる |
| 作品 repo(GitHub) | 低 | public、再生成可 |

### 推奨する境界(→ 2026-09-13 に決定へ。decisions/2026-09-13-permission-zones.md の 3 ゾーン方式に置き換え。以下は却下した初案)

1. **G: から社外ドライブのショートカットを外す**(最優先、今日できる)。AI から見える Drive は `G:\マイドライブ\ai\` のような専用フォルダに限定する。
2. **AI に開くローカルルートを `E:\ai\` 1 つにする**。ゲーム repo は全部その下に移す。仕事フォルダは E: 直下から別の場所へ(または AI が読めない設定に)。Claude Desktop / Cowork で許可するフォルダをそこだけにする。
3. **社外ドライブへの反映は「配達係」を分ける**。AI は `ai/outbox/` に成果物を置くまで。そこから社外ドライブへコピーするのは人間が起動する GAS / Python(コピー先とファイル一覧を表示して確認を取る)。
4. **Google アカウントの分離は第 2 段階**。ショートカット除去とフォルダ限定で当面の危険は消える。分離は 5TB の帰属とコストを見て判断。
5. Chrome 拡張は仕事の SaaS にログインしたプロファイルでは使わず、**開発専用 Chrome プロファイル**で使う。

## 検討中の論点

1. **権限の棚卸し(最初にやる)**。AI が触れるものを 1 枚の表にする。
   | 種類 | 具体例 | 今の許可 | 触られると困る度 |
   |---|---|---|---|
   | ローカル PC のフォルダ | Cowork / Claude Desktop に開いているフォルダ、`E:\` 配下 | ? | 仕事フォルダは最大 |
   | GitHub | `AI_OPS_TOKEN`(全 repo の Administration 権限)、各 repo の Actions secret | ai-ops に記録あり | 高 |
   | Google | GAS のスコープ(Drive 全体か特定ファイルか)、スプシ編集権 | ? | 仕事のスプシが同じアカウントなら高 |
   | 外部サービス | itch.io API キー、X、note | 作品 repo の secret | 中 |
   | Claude Code の設定 | 各 repo の `.claude/settings.json` の allow リスト、Cowork の自動承認 | ? | 中 |
2. **境界の設計案**
   - PC: AI に見せるのは `E:\ai\` のような **専用ルート 1 つ**だけ。仕事フォルダは別ドライブか別アカウント。Cowork / Desktop で開くフォルダをそこに限定する。
   - Google: 開発用の Google アカウント、または開発用の共有ドライブを分け、GAS はそちらのスコープでだけ動かす。5TB の Drive はどちらに属するか確認。
   - GitHub: 作品 repo は public なので壊れても再生成できる。ai-ops の全 repo 管理トークンは **使う時だけ有効化**、普段は失効させる(ai-ops 自身も「短命」と書いている)。
   - 秘密情報: 1 か所(パスワードマネージャー)に集め、どの AI がどれを持つかを表で管理。
3. **把握する方法**を仕組みにする。月 1 で「権限の棚卸し表」を Routine が更新し、変更点だけ報告する。
4. **壊した時の復旧**: Git は履歴で戻せる。Drive は版履歴 30 日。ローカルはバックアップの有無を確認。

## 棚卸しで見つかった要対応(2026-09-13)

- **fb-radio-auto(private)に Facebook のセッション cookie(cookies.json、datr / fr など 6 件)がコミットされている。** private でも履歴に残る。対応: (1) Facebook 側でセッションを無効化(全デバイスからログアウト)、(2) ファイルを削除し `.gitignore` に追加、(3) 履歴からも消すなら repo を作り直すのが最も簡単。→ 2026-09-13 ユーザー承認後、ファイル削除と .gitignore を push 済み。残りは Facebook 側の全デバイスログアウト(ユーザー)。

## E ドライブの棚卸し(2026-09-13 追加)

- GitHub に本体が無い過去作がある(doroneko / GGJ2025)。E: 直下の未整理ローカル repo を一覧化し、未 push のものを push する作業を、AI に開くフォルダを決める時に一緒に行う。
