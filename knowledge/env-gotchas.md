## クラウドのセッション同士のやりとり(2026-10-06)
- 親から子へは send_message で送れる。子から親へ直接返信する仕組みは無い(仕様)。
- 回避策: 子は `create_trigger`(persistent_session_id=親の session id、run_once_at=数分後)を使えば、親のセッションにメッセージを1回届けられる。未検証。
- いちばん確実なのは repo の HANDOFF.md に書いてもらい、親が読みに行くこと。

## クラウドのセッションから届かない・壊れるもの(2026-10-08 obake-chochin / kutsuzure)
- 公開した Pages(github.io)をクラウドから開けないことがある。「ちゃんと動く?」には、CI の公開の成否と公開された版(コミット)を API で確かめ、同じ版を手元でビルドして遊ばせて答える。返事に書く URL は 1 文字ずつ確かめる(打ち間違えたリンクを渡した例あり)。
- URL の直後に日本語や括弧を続けない(「公開済みです(https://…/)。」は「)。」まで URL と読まれて壊れる)。URL は単独の行に置くか `<URL>` で囲む。
- 素材サイト: 効果音ラボ・OtoLogic・freesound・itch.io・pixabay・archive.org は通らない。魔王魂・DOVA・Kenney・OpenGameArt・GitHub(VSCO-2-CE 等)は通る。生成 AI の API は鍵が無い(topics/06 の 2026-10-08)。
- GitHub の検索 API は 403。SVG → PNG は ImageMagick に rsvg が無いので、Playwright の Chromium に executablePath を渡して描く。

## my-rss のファミ通が 0 件になり、失敗メールが毎日来た(2026-10-11)
- 原因: ファミ通がページの部品名を `ArticleList_list` から `ArticleList-module-scss-module__aEPNzW__…`(ハッシュ付き)に変えた。目印が合わず 0 件 → 3 回連続失敗で実行が「失敗」になり、毎回メール。
- 直したこと(my-rss dd872ee・5e33edb): 目印を `[class*='PrimaryCard-module'] a[aria-label]` のような**ハッシュに頼らない部分一致**に変更(50 件取れるのを確認)。通知は **3 回目の 1 度だけ**にした。0 件の時はページ本文ではなく**構造の手がかりだけ**を `debug/<サイト>.txt` に残す(クラウドからファミ通に届かなくても、それを読めば目印を直せる)。
- 教訓: 他人のサイトから取る仕組みは、部品名のハッシュが変わると必ず壊れる。目印は部分一致で、壊れた時に構造が見える仕組みを最初から入れる。

## 権限モードの上限はクラウドとローカルで違う(2026-10-11 確認)
- クラウドのセッション: 選べるのは「編集を承認 / プラン / 自動」。**自動が最上位**で、「権限をバイパス」は無い。設定ファイルに bypassPermissions と書いても無視される。取り返しにくい操作(repo をまたぐ書き込み・外部への公開など)は自動でも止まる。
- repo の `.claude/settings.json` の allow ルールは、**repo を 1 つだけ付けたセッションでしか読まれない**。会議室のように repo を多数付けたセッションでは効かない。
- ローカル(PC の Claude Code・デスクトップアプリ): 自動の上に「権限をバイパス」がある(組織の設定で禁止されていなければ)。PC のファイルを確認なしで触るので、使うなら作業フォルダ(ゾーン A)に限る。
- Codex(ChatGPT デスクトップ)との対応: 「承認を求める」≒ Claude の「編集を承認」(作業フォルダ内の編集と普通のコマンドは自由、ネットと外は聞く)/「代わりに承認」(Auto-review。審査役の AI が代わりに許可)≒ Claude の「自動」/「フルアクセス」≒ Claude ローカルの「権限をバイパス」(PC 全体・ネットも確認なし)。Codex の後ろ 2 つは 設定 → 一般 → 権限 で有効にしないとメニューに出ない。出典: https://developers.openai.com/codex/concepts/sandboxing

## クラウドのセッションで外の道具を npx で試すと止められる(2026-10-12)
- REA(`npx -y rea-agents@latest …`)を自分の雛形の `dist/` に向けて試そうとしたら、自動モードの審査で「外部のコードの実行」として止められた。会議室のクラウドでは、新しい道具の試運転はできないものと考える。
- 試すなら PC で(作業フォルダの中、作品の repo ではない場所に解析対象を置く)。会議室には「どの PC で、何に向けて、何が返ったか」だけ書く。

## PC の Claude Code が API の従量課金でログインしていた(2026-10-12)
- 症状: デスクトップ PC の PowerShell で `claude` を起動すると、起動画面の左に「Fable 5 · API Usage Billing · <組織名>」。Max の枠ではなく Anthropic Console(API)の従量課金で動いていた。
- 直し方: `/logout` → 作業フォルダ(E:\dev)で `claude` を起動 → ログイン方法で「Claude account with subscription」を選ぶ。起動画面に「Claude Max」と出れば正しい。
- 確かめ方: 起動画面の左下の小さい文字(モデル名・契約名)を見る。「API Usage Billing」なら従量課金。Console の請求画面で使った額も確認する。
- ついでに: ホームフォルダ(C:\Users\<名前>)で起動すると「このフォルダを信頼するか」を聞かれる。信頼すると PC の個人ファイル全体に手が届くので、作業フォルダで起動する。既定のモデルが Fable(一番重い)になっていたら `/model` で Opus 5.5 か Sonnet 5.5 に下げる。

## SNS のリンクはアプリ内ブラウザで開く(2026-10-13 雛形に対策)
- LINE・Instagram・Facebook・X・TikTok から来た人は、アプリの中のブラウザで遊ぶ。音・全画面・横向き・保存が効かないことがある。
- 雛形の `src/core/inapp.ts` が自動で上に「ブラウザで開く」を出す。LINE は公式の `openExternalBrowser=1` で自動的に外部ブラウザへ。Android は `intent://`、iPhone は `x-safari-https://`(iOS 17 以降で動くという報告。iOS 16 は不可)と URL のコピー。
- 未確認: 各アプリでの実機の動き(特に iPhone の Instagram・X)。遊んだ人の報告で【実測】に上げる。
