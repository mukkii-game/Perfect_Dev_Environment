# 元ネタから始める(下調べの手順)

作品はたいてい「◯◯みたいなの」から始まる。いきなり作り始めると、元ネタが解いた問題を一から解き直すことになる。
書き始める前に 15 分ほど調べて、出発点を決める。
(調べる手順なので、AI に毎回守らせる指示ではない。雛形には入口の 1 行だけ置く)

## 手順
1. **元ネタを特定する。** 作品名、または「◯◯系」と呼ばれる型の名前。
2. **欠かせない要素を 3〜5 個に絞る。** その作品を遊んだ人が「これがあれば◯◯だ」と思う手触りを挙げる。
   ジャンルの定石は `tables/genres.csv` にある。
3. **公開されているコードと仕様を探す**(上から順に):
   - GitHub で `<作品名> clone` / `<作品名> phaser` / `<ジャンル> javascript` を検索する。スター数と最終更新日を見る。
   - itch.io の open source タグ。GDC の講演や開発者の解説記事(数値や仕様が書いてある)。
   - ジャンルの「作り方」解説: Red Blob Games、ゲームプログラミングのパターン集など。
   - 素材は `tables/assets.csv`、道具は `tables/ai.csv` から当てる。
4. **使い方を決める**(ライセンスで分かれる):
   | ライセンス | 使い方 |
   |---|---|
   | MIT / BSD / Apache / CC0 | そのまま取り込んでよい。`CREDITS.md` と `tables/used-assets.csv` に記録する |
   | GPL / AGPL | 取り込むとこちらも GPL になる。構造や手法を読むだけにする |
   | ライセンスの記載が無い | 著作権者に全権利がある。読んで学ぶだけにし、コードは写さない |
5. **結果を `SPEC.md` の冒頭に数行で書く**(元ネタ、欠かせない要素、土台にしたコードの URL とライセンス)。

## 地雷
- **ゲームのルールは真似してよいが、名前・絵・音・文章は真似できない。** 商標やキャラクターに寄せすぎない。
- 古い clone(Phaser 2/3 時代など)はそのまま動かないことが多い。写すのは構造だけにし、API は今のもので書き直す。
- 探すのは 15 分まで。見つからなければ自作する。探し続けて始まらないのが一番の損。
