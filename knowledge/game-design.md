# ゲームデザインの型(引くためのもの)

面白さの作り方・調整の型。外の記事や自分の作品で、効くと分かったもの。
実機の実装ノウハウは雛形の `docs/knowledge/`。教科書・単元は `tables/learning/`。

最終確認: 2026-10-08(3〜6 は作品セッションの回収: おばけ提灯・くつずれ)

## 1. 「手応え」と「難しさ」は別のつまみ(でぶねこ『猫ピンボール』制作記より)

- 楽しさを 1 つのパラメータで見ない
- **手応え**は UI・音・光で作る
- **難しさ**は障害物の大きさ・配置・ボールの速さで作る
- 「必ず死ぬ所」を潰すとぬるくなる → 落とし穴を「どこに飛ぶか分からないワープ穴」にして、ミスを罰でなく予想外の動きに変えた
- AI との作業: 参考画像は最初の依頼で渡す。不具合は起きた瞬間のスクショを渡すと文章より早く直る

**効く理由**: 難しさを下げても手応えは下げずに済む(逆も)。調整パネルのつまみも 2 系統に分けて並べられる。
AI で実装が速くなった分は、完成の短縮ではなく「遊ぶ回数」に回す。
出典: https://qiita.com/dev_cat222/items/ec807bd624d3e3b91d59 (2026-10-07、確認 2026-10-08)

## 2. 自由な地図には近い目標を見せる(shunchobi『ソリティア世界旅行』1.1 の改善記録より)

- 実例: 「どの街へも行ける」自由さを前に出した 1.0 で、2 つ目の街に着いた人は **19%**(初回から 8 日以上の 37 人)。遊ばせた人の声は「どう遊べばいいか分からない」
- 命令せず、**行くと得をする近い場所を見せる**(ゼルダ BotW の「引力」が手本)。ゴールが近いほど人は動く。2〜4 個から自分で選ぶと意欲が上がる
- 決めた設計: 地域は選ばせず、街を選ぶと裏で地域の達成率が上がる / 今の目標の地域に旗 / 地域と国の 2 段階で祝う / **最初の地域は簡単にして、早く「制覇」を味わわせる** / まとめ方はテーマ別より地理的な近さ
- AI の使い方: 類似事例の調査と案出しは AI、採用の判断とプレイ感での微調整は人間

**効く理由**: 自由度の高い作品ほど、最初の一歩の目標が無いと離脱する。数字で離脱が見えた実例。
注意: 1.1 の効果(19% が上がったか)はまだ測られていない。
出典: https://zenn.dev/shunchobi/articles/solitaire-world-tour-purpose-design (2026-10-07、確認 2026-10-08)

## 3. 名作は「動詞」で混ぜ、ひらめきは採点してから入れる(おばけ提灯 2026-10-08)

- 元ネタごとに動詞を 1 つ: ミサイルコマンド = 先を読んで撃つ / 平安京エイリアン = 仕掛けて待つ / ボンバーマン = 並べて誘爆。それぞれを 1 つの操作に割り当て、1 つの物の一生にまとめる。舞台は「道を読めるようにする」ために選ぶ
- 人間のひらめきは「見て分かる / 題材と合う / 深さ / シンプル / 操作が増えないか」で 5 点満点を付け、低い所だけ別の形に置き換える。採点は DECISIONS に残す

## 4. 情報はサインでなく、物そのものに持たせる(おばけ提灯 2026-10-08)

- 形 = 性能: 火の見櫓 = 上へ、軒の提灯 = 下へ、丸い蔵 = 周り。シルエットは遠目でも分かり、選ぶ操作(家をタップ)にもつながる
- 模様 = 効き方(キャンディクラッシュのしま模様)。字(飛・角)は読める人にしか通じないが、模様は誰にでも通じる
- 敵の通り道の線は「予測の答え」になって楽しさを消す。読ませたいのは動き方の決まりで、線では見せない
- 置いた後に光らせるより、**置く前に**(押している間に)離せばどうなるかをうっすら見せる。線で囲むと人工物っぽいので、薄い塗り + 縁をほんのり明るく
- 格子に置く(囲碁)と道が細く迫力が出ない。マスに置く(将棋)と光がマスを埋める。壁はマスそのもの(ボンバーマンの柱)と細い線(ドルアーガの板塀)を混ぜると迷路らしさと見通しが両立

## 5. 「何もしなくても勝てる」「手が止まる」を潰す(おばけ提灯 2026-10-08)

- 敵どうしの連鎖は、どこに当てても列ごと消えて工夫が要らなくなる。連鎖はプレイヤーが置いた物の間だけ。敵には「止まる・詰まる」(ディグダグ)のような利用できる性質を持たせる
- 弾を刻ごとの補充だけにすると、使い切った後はただ見ているだけになる。時間で少しずつ戻す
- 敵の出口が見えて届くと、出口で待ち伏せするだけになる(bot がそれで勝った)。画面の外から入らせる
- bot で「一番楽な勝ち方」を探すと設計の穴が見つかる(「家の前で待つだけ」が最強だった)

## 6. bot で面白さを確かめる型(おばけ提灯・くつずれ 2026-10-08)

- **型ごと × やり方の違う bot** で比べる: 面(刻)を 1 つずつ切り出し、先読みする / しない / 狙った手を使わない / まとめて取れるまで待つ、の bot で 1 手あたりの成果を並べる。狙った手が一番得になるまで数値を直す(狙った手が一度も使われていなかった例)
- 難しさは「人に近い bot」で測る: 反応の速い bot だけだと敵を速くしても成績が変わらず「まだ易しい」と誤解する。指が 0.6 秒遅れる bot を並べると、横の敵を 1.3 倍 → 1.8 倍にしただけでクリア 7 割 → 3 割と分かった(おばけ提灯 10/8)
- 「考えて置く bot」と「適当に押す bot」を同時に測ると、戦略の効き具合が数字で分かる(差が小さければ考える意味が無い)。おばけ提灯・くつずれに続き 3 本目の作品で同じ結論(2026-10-10)
- すぐ撃つ bot だけでは仕組みの上限を測れない。欲張らない bot を別に用意して、上手い人の上限(連鎖数など)を測る。すぐ撃つ bot だけで「連鎖が少ない」と判断すると正しい仕組みを壊す
- 正解のある面は「手本 + 自動の確かめ」とセット: 面のデータに手本(何秒にどこを押すか)と目標点を持たせ、描画なしで「手本は届く」「間違いの手は届かない」を確かめる。CI で回せばルール変更で面が壊れたことがすぐ分かる。手本はそのまま「正解の一例」ボタンにもなる
- 「選択に意味があるか」はルールの細部で消える(向きを選ばせたのに、どの向きでも当たっていた)。わざと間違えた手を流して、差が結果に出るかを数字で見る
- 描画なしの bot で「歩き方 5 通り × 最後まで」を回すと、山場が起きない・終わらない等の致命傷が 1 秒で出る。さらに別の AI に「辛口のディレクター」としてレビューさせると、自分で見えない穴(山場が画面の外で起きている)が出る(くつずれ)
- **回数は 1 案 400 回**: 100 回以下だと同じ案でも ±5 ポイント揺れ、案の良し悪しを取り違える(おばけ提灯 2026-10-13)
- 雛形の入口: `core/probe.ts`(状態を文字で・意味単位の操作)、`core/replay.ts`、作品の `tools/sim.mjs`

## 7. 物理で合体するゲームの連鎖(作品セッション 2026-10-10)

- 合体すると 2 個分の幅が 1 個に縮み、となりとのすき間で連鎖が切れる
- 連鎖を狙わせるなら、生まれる位置を「次の大きさの仲間」の側へ寄せると連鎖が伝わる

## 8. 原理の一覧(層 0)

どのジャンルにも効く、抽象的な考え方。`tables/pieces.csv` の「狙う体験」列と `genres/_families.md` はこの名前で書く。
1 つの仕掛けが 2〜3 個を同時に狙ってよい(例: 『Inscryption』は 落差 → 自分の手柄 → 余韻 の連続)。
確かさの印は `genres/_families.md` と同じ。「Mukkii の方針」は本人への聞き取り(2026-07-23)で決めた考え。

| 名前 | 一言 | 効く場面 | 逆効果になる時 | 代表例 | 出典・確かさ |
|---|---|---|---|---|---|
| リスクとリターン | 危ないほど得をする | 稼ぎ・近接攻撃・寄り道・貯めるか使うか | 得が小さく誰も危険を取らない / 得が大きすぎて安全策が損しかない | 『星のカービィ』の吸い込み(敵に近づく危険とコピー能力)、STG のかすり点 | 【定説】桜井政博のゲーム作るには / Boghog's shmup 101 |
| 緩急(ペーシング / pacing) | 張り詰めた後に必ず息をつかせる | 面の並び・ボス前・物語の山場 | 波が読まれて飽きる(時々わざと崩す) / 谷が長すぎて離脱 | ボス前の休憩部屋、ホラーの静かな廊下 | 【定説】Dan Taylor「Ten Principles for Good Level Design」(GDC 2013)/ Raph Koster の難しさの波 |
| 差で見せる(コントラスト) | 人は差が無いと気づかない | 強い敵・大事な物・山場を目立たせる | 何もかも強調して、どれも目立たない | 暗い場面の後の明るい場面、雑魚の後の巨大ボス | 【一説】CEDEC2016 大野功二「コントラストで考えるゲームデザイン・レベルデザイン」 |
| 読み | 先を予測して、当たる | 弾避け・迎撃・相手の手・敵の巡回 | 情報が隠れすぎて当てずっぽう / 答えが線で見えて予測が要らない | ミサイルコマンドの先読み、将棋 | 【実測】おばけ提灯(§4 の通り道の線)/【定説】 |
| 自分の手柄 | 気づいたのは自分だ、と思わせる | 謎解き・隠し要素・攻略法の発見 | 導線が親切すぎて解かされた感じになる / 放置しすぎて誰も気づかない | 『Outer Wilds』(知識だけが先へ進める鍵)、『Öoo』 | Mukkii の方針(ライト層には適度な誘導は可)/【定説】 |
| 落差 | 期待を仕込んでから裏切る | 物語の転換・ジャンルの前提崩し・ボスの第 2 形態 | 仕込み(期待の設営)が無く、ただの不意打ち / 何度も使って予想される | 『Inscryption』、『女神転生 II』の世界の崩壊と全財産の消失 | Mukkii の方針 |
| 習熟の確認 | 前に苦労した所を楽に越えさせる | 終盤の面・2 周目・昔の敵の再登場 | 楽すぎて作業になる / 確認の場が無く上達を感じない | 序盤のボスが雑魚として出る、最初の面の再訪 | 【一説】Dan Taylor(上記)の「反復による習熟」 |
| 学びの導線 | 教える → 試す → ひねる → まとめ | 新しい仕掛けを 1 つ入れる時 | 説明文で教える / ひねりの前に試す場が無い | 『スーパーマリオ 3D ワールド』の面の作り | 【定説】GMTK「Super Mario 3D World's 4 Step Level Design」/ Celia Hodent「The Gamer's Brain」(GDC) |
| 選択の重み | どれを選んでも同じなら選択ではない | 報酬の 3 択・ルート分岐・装備 | 正解が 1 つ(支配戦略) / 差が小さくて見えない | 『Slay the Spire』のカード 3 択 | 【定説】Sid Meier「Interesting Decisions」(GDC 2012)/【実測】bot で考える意味を測った 3 作品(§6) |
| 運の置き場 | 運は選ぶ前に置くと計画を生み、選んだ後だと計画を壊す | ローグライク・カード・命中判定 | 選んだ後の運が多すぎて腕が結果に出ない | 配られた手札(前)、命中率 95% の外れ(後) | 【定説】GMTK「The Two Types of Random in Game Design」/ Geoffrey Engelstein『GameTek』 |
| 近い目標と遠い目標 | すぐ届く目標と、憧れの目標を同時に見せる | 自由な地図・育成・長く遊ぶ作品 | 近い目標だけで先が見えない / 遠い目標だけで手が止まる | 次のレベルまでの経験値表示、BotW の「引力」 | 【定説】桜井政博のゲーム作るには / §2 |
| 手応え(ゲームフィール / game feel・juice) | 押した瞬間に光・音・揺れで返事する | 全ての操作、特に攻撃と得点 | 演出が多すぎて状況が読めない(読みを壊す) | ヒットストップ、得点の数字が飛ぶ | 【定説】Steve Swink『Game Feel』/ §1 |
| 失敗の安さ | 負けてもすぐ、もう一度 | 難しい ACT・パズル・ローグライク | 安すぎて考えずに突っ込むだけになる | 『Celeste』の即座の復帰 | 【一説】GDC「The Jetpack Joyride Postmortem」 |
| 公平な負け | 負けを自分のせいだと思える | 即死・初見殺し・対戦・運の結果 | 理由が見えない負け(画面外・判定のずれ・選んだ後の運) | 当たり判定を見た目より小さくする STG | 【定説】`genres/shmup.md` |
| 寄り道の得 | 行くと少し得をする所を本道の脇に置く | 探索・地図・経営のランダム出来事 | 寄り道が必須になってやらされ感 / 得が無く誰も寄らない | 本道から見える宝箱、「ちょっと儲かりそうだから寄る」 | 【一説】Dan Taylor(上記)の非線形探索への報酬 / Mukkii の方針(自発的な動機の言葉) |
| 意外なごほうび | 予告しないごほうびは、遊ぶ理由を奪わない | 収集・実績・隠し要素 | 予告されたごほうびばかりで「ごほうびのため」に遊ぶ作業になる | 隠し部屋の思いがけない報酬 | 【一説】GMTK「This Psychological Trick Makes Rewards Backfire」(過正当化効果) |
| 作業に意味を与える | 同じ操作でも、意味・緊張・期待・報酬が付くと遊びになる | 単調な繰り返しの操作 | 意味づけが説明だけで、緊張や期待が無い | 文字入力を魔法の詠唱にする | 【一説】CEDEC2026『スペルトナエル』の講演 |
| 欠点の反転 | ふつうは減点される性質を、作品の芯にする | 単調・不便・遅さが題材と合う時 | 狙いを言わずに欠点を放置した言い訳になる | 『花と太陽と雨と』の単調さ | Mukkii の方針(チェック項目に「ただしこれが成立する時を除く」と書いてよい根拠) |
| 余韻 | 遊び終わった後に、人に話したくなる | 結末・大きな落差の直後・珍しい出来事 | 話したくなる要素が遊びの芯から外れている | 『Undertale』の結末 | Mukkii の方針 |
| コアループ(core loop) | 数十秒〜数分で一周する「やる → 返事が来る → 得る → また やりたくなる」の輪。外側に 1 プレイの輪(ゲームフロー)、さらに外側に長期の輪(メタ進行)を重ねる | 企画の最初・1 日パイロット・「何が面白いの?」と聞かれた時 | 輪が回るだけで判断が無い(作業) / 外側の輪の報酬が内側の楽しさを食う | STG の「撃つ → 避ける → 稼ぐ」、ローグライクの「戦う → 選ぶ → 強くなる」 | 【定説】海外のゲームデザイン講座の基本語(GDC 等)。会議室では genres/<ジャンル>.md の §1「芯」と §2「ゲームフロー」がこれに当たる |
| 視線誘導 | 見てほしい所に、光・色・形・動き・線で目を連れていく | 面の入口・次に進む道・押してほしいボタン・危険の予告 | 誘導が強すぎて「やらされ」になる(自分の手柄を壊す) / 飾りが目を奪う | 暗い道の先の明かり、黄色い取っ手(登れる印) | 【定説】レベルデザインの基本(差で見せる と組む)。情報を物に持たせる(§4)と同じ考え |
| タメ・ツメ・フォロースルー | 動きを「予備動作(タメ)→ 一瞬で決める(ツメ)→ 余韻の動き(フォロースルー)」に分けると、重さと気持ちよさが出る | 攻撃・ジャンプ・カードを出す・ボタンを押す演出 | タメが長すぎて操作が遅れて感じる(入力への返事は即座に) | 格闘ゲームの攻撃モーション、振りかぶってから振り抜く斧 | 【定説】アニメーションの原則(溜め・詰め、Disney の 12 原則の anticipation / follow through)。雛形 docs/knowledge/controls.md「手触りの地雷」の「振りかぶりは短く」と組む |

用語の対応(2026-10-16): 欧米のゲームデザイン理論の言葉で頼まれても、この表の名前で引ける(pacing = 緩急、game feel / juice = 手応え、core loop = コアループ、ゲームフロー = 各 genres の §2)。

使い方の注意(Mukkii の方針): 企画やピースには「どの原理を、どの仕様で、意図して狙うか」を書く。狙いが書いてあれば、外れた時に直せる。
効いたかどうかは、遊んだ人が自分から「気になる」「埋めたい」「今しかない」「寄っておこう」と言う・動くかで見る。続けて遊んでいても、狙った芯でない所が理由なら失敗(続く理由を必ず言葉にしてもらう)。

### よく組む組み合わせ
- コアループ + 手応え + タメ・ツメ・フォロースルー: 一番よく繰り返す操作こそ、返事と動きを磨く(四角のままでも楽しいかを先に確かめ、その後に手応えと音を足す)。
- 学びの導線 → 習熟の確認: 教えた仕掛けを、後半で楽に越えさせて上達を見せる。
- 緩急 + 差で見せる: 谷の静けさが、次の山を大きく見せる。
- 読み + 公平な負け: 読める情報を見せていれば、負けても自分のせいだと思える。
- 落差 → 自分の手柄 → 余韻: 前提が崩れたことに自分で気づくと、人に話したくなる。
- リスクとリターン + 失敗の安さ: 失敗が安いほど、人は危ない方を選ぶ。

### bot で確かめられる原理(雛形の `bots.ts` / `npm run sim`)
| 原理 | 何を比べるか |
|---|---|
| 選択の重み | 「でたらめ」と「考える」の成績の差。小さければ選ぶ意味が無い(§6) |
| 読み | 先を読む bot と読まない bot の差。差が無ければ読む必要が無い |
| リスクとリターン | 危険を取る bot と取らない bot の点と生存率。どちらかが常に勝つなら釣り合っていない |
| 公平な負け | 「考える + 指の遅れ」bot の負けた場面を集め、避けようのない負けが無いか見る |
| 近い目標と遠い目標 | 次の目標まで何秒かかるかの推移。急に長くなる所で手が止まる |
| 手応え・落差・自分の手柄・余韻 | bot では測れない。人が遊んで、自分から出た言葉と動きで見る |
