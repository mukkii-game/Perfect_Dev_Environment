# エンジンの選び方(引くためのもの)

**既定は Web / ブラウザ / JavaScript。** これは速さのための選択で、公開が最短(push → Pages)、
AI が最も正確に書け、どの端末でも遊べるため。**ここから外れるのは、外れる理由がある時だけ。**

最終確認: 2026-10-01

## 作品の形から引く

| 作りたいもの | 使うもの | 外れる理由 |
|---|---|---|
| 2D 全般・テキスト中心・小さいもの | **素の canvas / DOM + `src/core/`** | 過去 21 本中 13 本がこの形で最速に出ている |
| 2D で物理・TileMap・大量スプライト | **Phaser 4** + Vite + TS | 自前で書くと時間が溶ける領域だけ Phaser に任せる |
| 3D で動きが激しい(アクション・シューティング) | **Babylon.js** | 物理とエンジン機能が揃っている |
| 3D で見せるのが主(風景・展示・演出) | **Three.js** | 表現の自由度。作例と素材が多い |
| **3D で作り込む(ライブラリの充実が効くもの)** | **Godot 4** | **物理・ナビゲーション・アニメーション・UI が最初から揃っている。Web 書き出しもできる。「3D を Web で手早く」ではなく「3D をちゃんと作る」時はこちら** |
| 本格的な 3D・家庭用機/Steam での販売 | Unity | アセットストアと実績が最大。ただし Web 書き出しは重く、規約・料金体系の変動に注意 |
| 映像の美しさが売りの 3D | Unreal Engine | 画質は最高だが重く、個人の 1 日 1 本には全く合わない |
| スマホアプリとして出す | 未検討 | 今は Web で出して反応を見る段階 |

## Godot を選ぶ判断(2026-10-01 追記)

ユーザー提起:「3D ものは Godot の方がライブラリが最初から充実していて向くタイトルもある」。**その通り。**
Web/JS を既定にしているのは速さのためで、3D は**その前提が崩れる領域**。
Three.js や Babylon.js で 3D を作ると、物理・当たり判定・ナビメッシュ・アニメーション遷移・
UI を自分で組む割合が増え、「速いから Web」の理由が消える。

**Godot が個人に向く理由**(ユーザー指摘 2026-10-01):
- **完全無料**(MIT ライセンス。売上の取り分もない)。Unity・Unreal のような料金体系の心配がない
- **GDScript は Python に近い書き方**。AI が書きやすく、人間が読んで直しやすい
- エディタが軽い。Unity / Unreal より起動もビルドも速い

### トークン数も選択理由になる(ユーザー指摘 2026-10-01)

**エンジンが最初から持っている機能は、AI が書かずに済むコード**。物理・経路探索・アニメーション遷移・
UI を Three.js で自作させると、そのぶん毎回トークンを使い、直しでさらに使う。Godot に任せれば
その分が消える。GDScript が Python に近く短く書けるのも効く。

| | Web(素の JS / Phaser) | Godot | Unity / Unreal |
|---|---|---|---|
| AI がエンジンを知っている度合い | **最も高い**(学習量が圧倒的) | 中。**Godot 3 と 4 の書き方を混ぜて間違えやすい** | 高いが、プロジェクト構成が重い |
| 機能を自作させる量 | 2D は少ない。**3D は多い** | **少ない**(機能が揃っている) | 少ない |
| 書くコードの短さ | 普通 | **短い**(GDScript) | C# / C++ で長い |
| AI が触るファイル | コードだけ | コード + シーン(`.tscn` はテキストだが長い) | バイナリ混在で AI が触りにくい |

**逆向きの力(注意)**: AI が Godot 4 の正しい書き方を外すと、**直す往復でトークンが逆に増える**。
Phaser 4 で公式スキルを用意したのと同じ理由で、Godot を使う日は Godot 4 の参照資料を
入口スキル 1 枚で引けるようにしておく(必要になった時に作る)。

**結論**: 2D は Web がトークンでも最安。**3D で機能が要るものは Godot の方がトークンも安い**見込み。
ただし実測はまだ。最初の Godot 作品で「1 本あたりのトークン量」を測り、ここに書く。

**判断の目安**: 3D で**キャラが地形を歩き回る / 敵が経路探索する / アニメーションが複数状態を遷移する**
のどれかがあれば Godot。**見せるだけ・単純な動きなら Three.js / Babylon.js**。

**Godot の代償**(承知の上で選ぶ): Web 書き出しは読み込みが重くスマホで不利。
公開が Pages 直行にならない。`src/core/` が使えない。公開キットも作り直しが要る。
→ **1 日 1 本のパイロットには向かない。「これは作り込む」と決めた作品だけ。**

## 公開先から逆算する(2026-10-01)

**Switch 2 に出す可能性がある作品は、Web では作らない**(持って行けず作り直しになる)。
Unity と Unreal は Switch に公式対応、Godot は移植会社経由(要確認)。詳しくは `platforms.md`。
Steam はどのエンジンでも出せるが、Web 製は包む手間がかかる。

## 使わないもの

| | 理由 |
|---|---|
| Unity / Unreal を今の 1 日 1 本に使う | Web 向きでない。過去作に Unity 製があるが、今の方針(ブラウザ最短公開)と合わない。**作品の形が変われば(Steam 販売など)上の表で再検討する** |
| unityroom | Unity 専用。公開先として対象外 |
