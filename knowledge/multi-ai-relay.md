# 複数の AI を GitHub でつなぐ時の知見(Emmichy の実験から)

出典: mukkii-game/emmichy Issue #2 の [FINAL RELAY REPORT](2026-10-07、ChatGPT 側がまとめた)。
実験の中身: ChatGPT の Chat(監督役)と Cloud Work(実装役)を、GitHub の PR・Issue 経由で自動で往復させた。**結論は「やめて 1 本に集約」**。

## 効いたこと
- GitHub を共通の連絡場所にすること自体は有効。人間のコピペは大きく減った。
- 製品名ではなく役割(監督・実装・点検)で手順を書くと、Claude / GPT / Gemini のどれにも使い回せる。
- **軽量化(Fast Path)**: 毎回 SPEC・HANDOFF・PLAYTEST・Issue 履歴を全部読むのをやめ、「PR の最新の依頼 → AGENTS → 要るファイルだけ → 関係するテストだけ → 短い報告」にしたら、読み込み量・待ち時間・無駄な実行がはっきり減った。

## 壊れたこと
- **止まっている AI は自動では起きない。** 実装役が報告を書いても、監督役のチャットは目覚めない。穴埋めに実装役の中へ監督の代理を入れたら、役割が絡まって複雑になった。結局、人間に「送る/捨てる」を選ばせる場面が出た。
- **通知の中身を信じると止まる。** GitHub のイベントで起動はしても、通知にコメントの ID・URL・本文が欠けることがあった。安全側で止まり、「作業中」の印だけ残る幽霊が出た。
- **止まったのか動いているのか外から分からない。** 「作業中」にした後、commit も報告も中断理由も無いことがあった。

## 次にやるならこの形(実験の結論)
1. 連絡の場所は 1 つだけ。
2. **イベントは「起床ベル」として扱う。** 起きたら、通知の中身ではなく PR・Issue を直接読んで、未処理の依頼を自分で探す。
3. PR の実データが正本。
4. **黙って終わらない。** 止まる時は理由を連絡の場所に書く。一定時間動きが無ければ「止まった」と判定する仕組みを持つ。
5. 自動の往復回数に上限を付け、超えたら「人間が要る(NEEDS_HUMAN)」で止める。
6. 役割で書く。状態の表示は短く。
7. 実 AI での品質確認は無料枠の上限(429)に当たりやすい。まずルールだけ・固定データ・関係するテストで詰め、最後に少しだけ実 AI で確かめる。

## うちの判断
- **小さな個人開発では、AI 同士の自動往復は作らない。** 1 本のセッションに監督と実装をまとめる方が安い(ChatGPT 側も同じ結論)。
- 会議室の今の形(HANDOFF.md で引き継ぐ、Claude の上限が来たら Codex に渡す、定期実行は「出力が届いたか」で確かめる)は、この知見と合っている。追加で取り入れるのは 2 つ:
  - 毎回読むファイルを増やさない(Fast Path)。雛形も「SPEC と HANDOFF だけ」を保つ。
  - 子のセッションや定期実行は、止まる時に必ず理由を残す(黙って終わらない)。
- 会話ゲームの作り方の知見は `ai-in-games.md` に移した。

## 調べ物を別の AI に頼む時の型(2026-10-12)
- AI 同士の直通は無い。Claude のクラウドセッション同士は話せるが、Codex・Gemini には届かない。**人間は「依頼書を読んでやって」と 1 回言うだけ**にし、受け渡しは決まった場所のファイルで行う。
- 共通の場所は、全員が読み書きできる所にする: 全員が PC で動くなら作品フォルダの `research/`、クラウドの Claude も使うなら GitHub の repo。
- 依頼書(1 枚)に書くこと: 目的(何の判断に使うか)/ 調べる範囲と出典の優先順位 / 作るもの(表の列を固定)/ 置き場所とファイル名(AI ごとに別ファイル)/ 分担 / 完了の形 / 禁止事項 / 終わった時の報告(状態ファイルに 1 行、止まる時は理由)。
- 分担の基本: 2 つの AI に同じ範囲を別々に調べさせ、統合と食い違いの確認は 1 者(依頼した側)がやる。同じファイルを同時に書かせない。
- **人間抜きにする一番確実な道は、PC のコマンド版を呼ばせること**: Codex・Claude Code・Gemini 系はどれもコマンド 1 行で頼める形を持つ(`claude -p "..."`・`codex exec "..."`・Gemini CLI の `-p`)。Codex が自分の端末で `claude -p "research/<題>/brief.md を読んでやって"` を実行すれば、各社の月額契約の枠で動き、終わり＝コマンドが終わる・ファイルができる。画面操作(ブラウザで各 AI のチャットを動かす)は遅く壊れやすいので使わない。クラウドでも月額の枠で呼べる道はある(2026-10-12 訂正): ① 会議室の Claude がクラウドの Claude セッションを立てる(create_session。くつずれで実績) ② GitHub Actions の claude-code-action に `claude setup-token` で作った CLAUDE_CODE_OAUTH_TOKEN を渡す(Pro/Max の枠。API キーを渡すと従量課金) ③ GitHub の PR で @codex と書くと Codex のクラウド作業が ChatGPT の枠で動く(Issue でも動くという記事あり)。どれも作品が GitHub に push されていることが前提。Codex をブラウザ(クラウド)で動かすと、PC の claude・gemini コマンドは呼べない。
- 要確認(2026-10-12 の検索。第三者の記事のみ): Gemini CLI は 2026-06 から Google ログインでの無料・AI Pro 利用が終わり、Antigravity CLI(`agy`)へ移ったという記事がある。Antigravity は Google AI Pro で Claude Sonnet/Opus 5.5 も使え、枠は Claude Max とは別、という記事もある(本当なら Claude の枠が尽きた時の予備になる)。
- Cursor・Manus は複数のモデルを選べるが、それぞれ自社の料金と枠で動く。手持ちの ChatGPT・Claude・Gemini の契約の枠は使わない。
