# 落ち物・マッチ系パズル(テトリス系、ぷよぷよ系、3 マッチ、物理マージ(スイカゲーム系))

使い方: 作る前に 1〜2 を通して読み、作りながら 3〜6、素材は 7、行き詰まったら 8。数値は「つまみ候補」として `src/tuning.ts` に入れ、F2 で人が直す前提の初期値。最終更新: 2026-10-12。
確かさの印: 【実測】うちの作品で確かめた /【定説】複数の出典が一致 /【一説】1 出典だけ。印の無い数値は、このファイルが置いた仮の値。
用語: ピース = 落ちてくる操作中の塊。ロック = ピースが盤面に固定されること。NEXT = 次に来るピースの表示。おじゃま = 対戦で相手に送り込む邪魔なブロック。G = 1 フレーム(1/60 秒)に何段落ちるか(1G = 毎フレーム 1 段)。
商標の注意: 「テトリス」「ぷよぷよ」「スイカゲーム」は他社の商標。ここでは仕組みの解説として名前を出すだけで、作品の題名・ロゴ・宣伝文には使わない。テトリスで流れる「コロブチカ」の編曲は The Tetris Company が音の商標を持つ【一説】tetris.wiki「Tetris Guideline」。

## 1. 芯と、1 日で作るパイロットの最小構成

### 芯(4 つの型に共通するもの)
- **積もる圧と、消す解放**: 放っておくと盤面が埋まって負ける。揃えて消すと一気に空く。この緊張と緩和を数秒ごとに繰り返す。速さは「消すたびに上がり、始まりは遅い」波で付ける【定説】GMTK「難度曲線」動画 / Raph Koster「Game design is simple, actually」(2025)
- **次を読んで置き場所を選ぶ**: NEXT を見て、今のピースをどこに置けば次が楽になるかを考える。ルールは 1 行で言えるほど単純で、遊ぶほど頭の中で繰り返される【一説】CEDEC2009 本山博文「ワールドワイドタイトルのゲームデザイン」
- **記録が終わらない目標になる**: 「全面クリア」のような絶対の目標は達成すると終わるが、ハイスコアは「次はこれを超える」で何十年も遊ばれる【一説】GMTK「This Psychological Trick Makes Rewards Backfire」

### 型ごとの芯
| 型 | 芯 | 典型 |
|---|---|---|
| テトリス系 | 4 マスの形を回して隙間なく並べ、横 1 列が埋まると消える。何列同時に消すかで点が跳ねる | 10×20 の盤、7 種の形 |
| ぷよぷよ系 | 同じ色が 4 つ以上つながると消え、上が落ちてまた揃うと「連鎖」。仕込んでから一気に発火する | 6×12 の盤、2 個組【定説】Puyo Nexus Wiki「Basic rules」 |
| 3 マッチ | 隣どうしを入れ替えて縦横 3 つ以上揃える。消えた所へ上から落ち、偶然また揃う(カスケード)。手数制限つきの面目標 | 8×8 前後、面クリア型【定説】Wikipedia「Candy Crush Saga」 |
| 物理マージ | 同じもの 2 つが触れると 1 段大きくなる。物理で転がるので置いた場所から動く。容器のふちの線を越えたら終わり | 全 11 段、落とせるのは小さい 5 種【一説】Wikipedia「Suika Game」 |

- ぷよぷよを 20 年以上続けた側は、本質を「対戦・シンプル(4 つで消える)・連鎖の爽快感・キャラ」の 4 つと定義し、それ以外は時代に合わせて変えてよいとした【一説】CEDEC2015「ぷよぷよIPのチャレンジと管理」
- 物理マージは「2048 に物理を足したもの」と評された。物理のせいで予想外のことが起き、入口は優しく奥は急になる【一説】Wikipedia「Suika Game」の各誌評

### 1 日パイロットの最小構成(テトリス系の例。この順で作る)
1. 盤面の配列と、ピース 1 つの落下・左右移動・回転(壁蹴りは後)・ハードドロップ。
2. ロック → 揃った列を消す → 上を詰める → 次のピース出現。上まで積んだら終わり。
3. 7 種 1 巡の袋(§3)と NEXT 3 個。ゴースト(落ちる先の点線枠)。
4. 10 列消すごとにレベルが上がり、落下が速くなる(§4 の式)。
5. スコアとハイスコア(`core/save`)。リザルトで「もう一度」が 1 タップ。
6. `?auto=1` で全部の置き場所を採点して置く bot、`?seed=` で再現(`core/rng`・`core/replay`)。
- 後回しでよいもの: ホールド、壁蹴りの完全版、T スピン、対戦、凝った消去演出。
- 物理マージなら: 円 5 種を落とす → 同じ大きさが触れたら 1 段上に置き換え → 11 段 → ふちの線を一定時間越えたら終わり → NEXT 1 個。物理は Matter.js(`tables/assets.csv` B ランク)。
- パズルは描画が軽いので、Phaser より素の canvas + 自作ロジックが向く【実測】`tables/genres.csv` / 非公開の作品(2026-10、`harvest-log.md`)

## 2. よく使うゲームシステムとゲームフロー

- **1 手の流れ**: 出現 → 落下 → 接地 → ロック猶予 → ロック → 消去判定 →(連鎖なら落として再判定)→ 次の出現までの短い待ち(ARE)。消去中は入力を受けない時間がある、という前提で状態を持つ(§3)。
- **NEXT**: 1〜6 個。盤面の右か上に置き、次に出るものを盤面に一番近くする。出現時と同じ向きで描く【定説】tetris.wiki「Tetris Guideline」
- **ホールド**: 今のピースを 1 個だけしまう。入っていれば入れ替え。ロックするまで再使用できない。7 種 1 巡の袋とホールドがあれば理論上いつまでも続けられる【定説】同上
- **ゴースト**: 落ちる先を半透明か枠線で出す。切れる設定を置くこともある【定説】同上
- **ゲームオーバーの条件**
  - テトリス系: ①出現位置が既に埋まっている ②ピースが見える盤面より完全に上でロックした ③おじゃまで押し上げられ、上の隠し行(バッファ)を越えた、のどれか【定説】tetris.wiki「Tetris Guideline」
  - ぷよ系: 出現位置(左から 3 列目の一番上)が埋まったら負け【定説】Puyo Nexus Wiki「Basic rules」
  - 物理マージ: 線を越えたら終わり【一説】Wikipedia「Suika Game」。越えた瞬間でなく「数秒越えたまま」で判定すると、跳ねた一瞬で死なない(うちは 3 秒)【実測】非公開の作品
- **点の付け方(テトリス系の現行)**: 1 列 100・2 列 300・3 列 500・4 列 800、それぞれ × レベル。難しい消し方が続くと 1.5 倍(Back-to-Back)、ロックごとに消し続けると 50 × 続いた数 × レベル(コンボ)。ソフトドロップ 1 段 1 点、ハードドロップ 2 点【定説】tetris.wiki「Scoring」
  - **T スピン**: T 形を回転で狭い所へねじ込むと加点。判定は「最後の操作が回転」かつ「T の中心の斜め 4 マスのうち 3 つが埋まっている」(3 隅判定)。壁や床は埋まっている扱い【定説】tetris.wiki「T-Spin」
- **連鎖の点(ぷよ系)**: 点 = 10 × 消した数 ×(連鎖倍率 + 色数ボーナス + 連結ボーナス)。倍率は 1 連鎖 0(=1 扱い)、2 連鎖 8、3 連鎖 16、4 連鎖 32、以降 32 ずつ増える(ぷよぷよ通の対戦用)【定説】Puyo Nexus Wiki「Scoring」「List of attack powers」
- **3 マッチ**: 4 つ以上揃えると特殊ピース(列消しなど)ができ、それを揃えると広く消える【定説】Wikipedia「Candy Crush Saga」。5 つで色ごと消す爆弾、L・T 字で爆発、という対応が多い【一説】Sugar Splash の README(公開の 3 マッチ実装)
- **面目標(3 マッチ)**: 手数制限の中で「点に届く」「床のゼリーを剥がす」「材料を一番下まで下ろす」「指定の色を何個集める」。星は点で 1〜3 個【定説】Wikipedia「Candy Crush Saga」/ summerengine の 3 マッチ解説
- **物理マージの段**: 11 段、落とせるのは小さい方の 5 種で順番は完全ランダム、次の 1 個だけ見える。最大どうしが合体すると消える【一説】Wikipedia「Suika Game」
- **対戦のおじゃま**
  - テトリス系: 2 列消し → 1 段、3 列 → 2 段、4 列 → 4 段、T スピン 2 列 → 4 段、T スピン 3 列 → 6 段、全消し → 10 段。届く前に自分が消せば打ち消せて(相殺)、余りは送り返す【定説】tetris.wiki「Garbage」
  - おじゃまの穴の列: 毎段ばらばらだと掘りにくく、揃いすぎると一気に消せて揺れが大きい。好みが割れる所【一説】同上
  - ぷよ系: 送る数 = 連鎖の点 ÷ 70(端数は次に持ち越し)。相手の連鎖で打ち消せる(相殺)。長引くと一定時間後から 1 個に要る点が 3/4、以後 16 秒ごとに半分になり、試合が終わる(マージンタイム)【定説】Puyo Nexus Wiki「Scoring」「Offset rule」「Margin time」
- **フロー**: タイトル → プレイ(1 回 2〜5 分)→ リザルト(点・最大連鎖・消した数)→ もう一度。面クリア型(3 マッチ・物理マージの目標付き)は面選択の地図を挟む。

## 3. よく使うデータ構造(この雛形での書き方)

雛形の決まり: 中身は `src/game/logic.ts` の `step(state, input, cfg)` で **1/60 秒(TICK)ずつ**進め、Phaser・DOM・`Math.random` を使わない。描画は state を読むだけ。

### 盤面と状態
```ts
// 盤面は 1 次元の配列。0 = 空、1〜7 = 色(形)。上に隠し行を持つ
export const W = 10, H = 20, HIDDEN = 4;               // ガイドラインの隠し行は 20 段。パイロットは 2〜4 で足りる
export interface Piece { kind: number; rot: 0|1|2|3; x: number; y: number }
export interface State {
  board: Uint8Array;            // (H + HIDDEN) * W。y は下向きに増やす
  cur: Piece | null; hold: number; holdUsed: boolean;
  queue: number[];              // NEXT。足りなくなったら袋を足す
  gravAcc: number;              // 落下の端数(段)。毎 tick 足して 1 を超えたら 1 段落とす
  lockTicks: number; lockResets: number;
  phase: 'play' | 'clearing' | 'are' | 'over'; phaseTicks: number; // 演出の待ちも tick で数える
  dasTicks: number; dasDir: -1|0|1;
  level: number; lines: number; score: number; tick: number; rng: Rng;
}
// 入力は「押されている」と「この tick に押された」を分ける。DAS/ARR は中身で数える
export interface Input { left: boolean; right: boolean; soft: boolean; hardP: boolean; rotCwP: boolean; rotCcwP: boolean; holdP: boolean }
```
- 消去アニメや連鎖の間を `phase` と残り tick で持つ。`setTimeout` で待つと、やり直し後に古いタイマーが新しい盤面を壊す(世代カウンタの話)【実測】雛形 `web-game-rules.md` §9-2(NeoSoukoban)
- ハードドロップ・回転は「押された瞬間」だけ効かせる。押しっぱなしで毎 tick 回ると壊れる。

### 7 種 1 巡の袋(7-bag)
```ts
function refill(s: State) {               // 7 種を 1 つずつ袋に入れて混ぜ、順に配る
  const bag = [1, 2, 3, 4, 5, 6, 7];
  for (let i = bag.length - 1; i > 0; i--) { const j = s.rng.int(0, i); [bag[i], bag[j]] = [bag[j], bag[i]]; }
  s.queue.push(...bag);
}
```
- 7 個ごとに全種が 1 回ずつ来るので「ずっと I が来ない」が起きない。偏りを抑える型(ローテーション)の代表【定説】tetris.wiki「Tetris Guideline」/ GMTK「The Two Types of Random in Game Design」
- 同じ形が続くのは袋の境目の 2 連までで、同じ形の間は最大 12 個空く(袋の仕組みから計算で出る)。

### 回転と壁蹴り(SRS)
- 形は 4 つの向きの表で持ち、回転は表を引くだけ。回した先がふさがっていたら、決まった 5 か所を順に試し、最初に入れた所へずらす(壁蹴り)。全部だめなら回らない【定説】tetris.wiki「Super Rotation System」
- J・L・S・T・Z は同じ表、I だけ別の表、O は蹴らない。表は **x 右が正・y 上が正**。盤面の y を下向きにしたら y の符号を反転して使う(ここを間違えると床で回らない)。
```ts
// 0=出現時, R=右へ 1 回, 2=2 回, L=左へ 1 回。[dx, dy](y 上が正)。tetris.wiki の表をそのまま
const KICK_JLSTZ: Record<string, [number, number][]> = {
  '0R': [[0,0],[-1,0],[-1, 1],[0,-2],[-1,-2]], 'R0': [[0,0],[ 1,0],[ 1,-1],[0, 2],[ 1, 2]],
  'R2': [[0,0],[ 1,0],[ 1,-1],[0, 2],[ 1, 2]], '2R': [[0,0],[-1,0],[-1, 1],[0,-2],[-1,-2]],
  '2L': [[0,0],[ 1,0],[ 1, 1],[0,-2],[ 1,-2]], 'L2': [[0,0],[-1,0],[-1,-1],[0, 2],[-1, 2]],
  'L0': [[0,0],[-1,0],[-1,-1],[0, 2],[-1, 2]], '0L': [[0,0],[ 1,0],[ 1, 1],[0,-2],[ 1,-2]],
};
const KICK_I: Record<string, [number, number][]> = {
  '0R': [[0,0],[-2,0],[ 1,0],[-2,-1],[ 1, 2]], 'R0': [[0,0],[ 2,0],[-1,0],[ 2, 1],[-1,-2]],
  'R2': [[0,0],[-1,0],[ 2,0],[-1, 2],[ 2,-1]], '2R': [[0,0],[ 1,0],[-2,0],[ 1,-2],[-2, 1]],
  '2L': [[0,0],[ 2,0],[-1,0],[ 2, 1],[-1,-2]], 'L2': [[0,0],[-2,0],[ 1,0],[-2,-1],[ 1, 2]],
  'L0': [[0,0],[ 1,0],[-2,0],[ 1,-2],[-2, 1]], '0L': [[0,0],[-1,0],[ 2,0],[-1, 2],[ 2,-1]],
};
```

### ロック猶予(ロックディレイ)
- 接地したら `lockTicks` を数え、30 tick(0.5 秒)でロック。接地中に動かす・回すとやり直しになるが、やり直しは 15 回まで(無制限にすると回し続けて永久に落ちない)【定説】tetris.wiki「Tetris Guideline」
- 1 段でも下に落ちたらやり直し回数を戻す実装が多い(段で戻す型)。

### 消去と連鎖の判定
- **列消し**: 各行が全部埋まっているかを見て、埋まった行を飛ばしながら下から 1 パスで詰め直す(`splice` を繰り返さない)。
- **ぷよ系**: 盤面全体を 4 方向の塗りつぶし(BFS)でつながりに分け、4 以上を消す → 浮いたものを落とす → もう一度、を消えるものが無くなるまで繰り返す。1 回ごとに連鎖数 +1。判定に隠し行を含めるかは決めておく。
```ts
function findGroups(b: Uint8Array, w: number, h: number, min = 4): number[][] {
  const seen = new Uint8Array(w * h), out: number[][] = [];
  for (let i = 0; i < w * h; i++) {
    if (!b[i] || seen[i]) continue;
    const g: number[] = [], st = [i]; seen[i] = 1;
    while (st.length) { const k = st.pop()!; g.push(k); const x = k % w, y = (k / w) | 0;
      for (const [nx, ny] of [[x-1,y],[x+1,y],[x,y-1],[x,y+1]]) { const n = ny * w + nx;
        if (nx >= 0 && nx < w && ny >= 0 && ny < h && !seen[n] && b[n] === b[i]) { seen[n] = 1; st.push(n); } } }
    if (g.length >= min) out.push(g);
  }
  return out;
}
```
- **3 マッチ**: 横と縦に走査して 3 連以上に印 → まとめて消す → 列ごとに落とす → 上から補充 → また走査。補充も `state.rng` で。
  - 初期盤面と補充で「最初から揃っている」を作らない(置く前に左 2 つ・上 2 つと同色なら引き直す)。
  - **手詰まりの検出**: 全部の隣接ペアを入れ替えてみて揃うか試す(8×8 なら 112 通りで軽い)。無ければ混ぜ直す。ヒント表示も同じ関数で出せる。
- **物理マージ**: Matter.js の `collisionStart` で同じ段どうしの接触を拾い、その tick の終わりにまとめて置き換える。1 つの玉が 2 組に入る二重合体を防ぐため「この tick に使った」印を付ける。
  - 生まれる位置は 2 つの中点が素直だが、合体で 2 個分の幅が 1 個に縮んで隣とすき間ができ、連鎖が切れる。**次の段の仲間がいる側へ寄せて生む**と連鎖が伝わる【実測】`game-design.md` §7
  - 物理は `Engine.update(engine, 1000/60)` を step の中で固定刻みで呼ぶ。描画の rAF から呼ぶと画面の Hz で結果が変わる。

## 4. よく使うゲームバランスの指針

| 項目 | 初期値(つまみ候補) | 根拠・印 |
|---|---|---|
| 盤面 | テトリス系 10×20 / ぷよ系 6×12 / 3 マッチ 8×8 | 前 2 つは【定説】tetris.wiki / Puyo Nexus。3 マッチは仮 |
| 落下の速さ | 1 段にかかる秒 = (0.8 − (L−1) × 0.007)^(L−1)。L1 = 1 段/秒、L10 ≒ 15 段/秒、L15 = 2.36G | 【定説】tetris.wiki「Marathon」(同じ値を別の解説も挙げる) |
| レベルが上がる量 | 10 列ごと、上限 15 | 【定説】tetris.wiki「Marathon」 |
| ロック猶予 | 30 tick(0.5 秒)、やり直し 15 回まで | 【定説】tetris.wiki「Tetris Guideline」「Lock delay」 |
| DAS(押しっぱなしで連続移動が始まるまで) | 10 tick(167ms) | 【一説】tetris.wiki(ガイドラインの「推奨・必須でない」値) |
| ARR(連続移動の間隔) | 2 tick(33ms) | 【一説】同上 |
| ARE(ロックから次の出現まで) | 6 tick(100ms) | 【一説】同上 |
| ソフトドロップ | その時の落下の 20 倍 | 【一説】tetris.wiki(Tetris Zone の値。作品で違う) |
| NEXT の数 | 3〜5 | 最大 6【定説】ガイドライン。数は仮 |
| ぷよが消える数 / おじゃま 1 個の点 | 4 / 70 | 【定説】Puyo Nexus Wiki |
| 物理マージ: 落とせる種類 / 全段数 | 5 / 11 | 【一説】Wikipedia「Suika Game」 |
| 物理マージ: 線を越えて許す時間 | 3 秒 | 【実測】非公開の作品 |
| 3 マッチ: 色数 / 手数 | 5〜6 色 / 20〜30 手 | 仮。色が少ないほどカスケードが増えて易しい |

- **出現の偏りを抑える**: 完全ランダムは「来ない」「続く」が起きて不公平に感じる。袋(ローテーション)や山札のように「一巡で全部出る」型にする【定説】GMTK「The Two Types of Random in Game Design」/ tetris.wiki。逆に出現を悪意で選ぶと地獄になる(常に最悪の形を出す HATETRIS)。出現の選び方そのものが難度のつまみ【一説】qntm/hatetris
  - 物理マージの「次 1 個だけ見える・完全ランダム」は、読み切れなさを残して運と腕を混ぜる設計【一説】Wikipedia「Suika Game」
- **速さは操作の複雑さと一緒に決める**: スマホ版で操作が複雑になった分、落下を遅くしたら退屈になった。ボタンを減らして速さを戻した【一説】GDC「Design in Detail」。置き場所を少数の候補から選ぶ操作にして速さとフローを取り戻した例もある【一説】GDC「Skill-Building Series: Emotion in Game Design (A UX Perspective)」
- **速さだけで難しくしない**: 20G(出現した瞬間に底)を過ぎたら、ロック猶予を縮めて難しくする【定説】tetris.wiki「Marathon」(上位モードの作り)
- **足して、削って、戻す**: 3 マッチは単純な核に面ごとのルールを少しずつ足して深さを出した。要素は壊れる手前まで削り、単調になったら 1 つ戻す【一説】GDC「Rules of the Game 2025」(Noah Falstein)
- **1 面の要素は 3〜4 個まで**、相性の悪い要素の組み合わせは表で禁止、ブースター(課金の助け)なしで必ず解ける【一説】Playrix 講演(White Nights、Game World Observer 2019)
- **難度は失敗率で測る**: 「負けた数 ÷ 挑戦数」。難しい面が 3 つ以上続くと離脱するので、山の後に易しい面を挟む【一説】同上
- **bot で測る**(雛形 `src/game/bots.ts` + `tools/sim.mjs`): 「考えて置く」と「適当に置く」を同時に回す。差が小さければ戦略が効いていない。うちの物理マージの試作では、考えて置く bot が 2〜3.5 分で目標達成、適当な bot が 47 秒であふれる所を採用した【実測】非公開の作品
  - テトリス系の考える bot は「全部の向き × 全部の列」にハードドロップした盤面を採点する(高さの合計・穴の数・でこぼこ・消えた列)。描画なしで 1 手 40 通り程度なので速い。
- **つまみ候補の一覧**(`src/tuning.ts`): `gravity.levelCurve`(上の式の係数)`level.linesPer` `lock.delayTicks` `lock.maxResets` `input.dasTicks` `input.arrTicks` `are.ticks` `soft.mul` `next.count` `hold.enabled` `ghost.enabled` `clear.animTicks` `chain.animTicks` `garbage.table` `garbage.holeRandom` `merge.spawnKinds` `merge.overLineSec` `merge.restitution` `merge.friction` `match.colors` `match.moves` `score.b2bMul` `score.comboBase` `audio.sfx` `audio.bgm`。曖昧な注文(「もっと気持ちよく」)は、このどれを何から何へ動かすかに直して返す。

## 5. よく使う攻略パターン・レベルデザイン

### テトリス系の定石(設計側は「この定石が報われる」点にする)
- **平らに積み、穴を作らない**。穴(上がふさがった空き)は掘るまで消えない。
- **端の 1 列を空けて 4 列消しを待つ**(井戸)。4 列消しは 1 列消し 4 回の 2 倍の点(800 対 400)で、Back-to-Back で更に 1.5 倍【定説】tetris.wiki「Scoring」。待つほど積みが高くなる = リスクとリターン。
- **T スピン用の穴を作る**: T 形の凹みを残しておき、回転でねじ込む。対戦では T スピン 2 列が 4 列消しと同じ 4 段を送る【定説】tetris.wiki「T-Spin」「Garbage」
- **ホールドは「今は要らない I を取っておく」「T をスピン用に取っておく」**。
- **コンボ**: 毎ロック少しずつ消し続けると加点。大きく待つ型と、細かく刻む型の 2 つの勝ち筋ができる【定説】tetris.wiki「Scoring」

### ぷよ系の連鎖の組み方
- **階段積み**: 同じ色を 1 段ずつずらして積み、下の組が消えると上が落ちて次の 4 つになる。**挟み込み**: 別の色で挟んで、落ちた時に揃う形。どちらも代表的な土台【定説】Puyo Nexus Wiki「Stairs」「Sandwich」「GTR」(連鎖の型の解説群)
- **発火点を最後まで残す**: 1 か所だけ欠けた状態で溜め、欲しい色が来たら火を付ける。待つほど大きく、待つほど危ない。
- **本線と催促**: 大きな連鎖を育てつつ、相手が育てる前に小さな連鎖で邪魔を送って急がせる(ハラスメント)【一説】Puyo Nexus Wiki の攻略ガイド目次
- 設計側: 連鎖倍率を連鎖数で大きく伸ばす(2 連鎖 8 → 10 連鎖 224)から「仕込み」が報われる【定説】Puyo Nexus Wiki。倍率を緩くすると早撃ちが強くなる。

### 3 マッチのステージ目標と面作り
- 面の流れは「考え方(アイデア) → 配置 → 作る → 調整 → テスト」。紙に描いてからエディタへ。設計者が「絶対面白い」と思った面の多くは面白くない、だから数字で直す【一説】GDC Europe 2016 King・Jeremy Kang(PocketGamer.biz 報道)
- 面に要る 4 つの柱: 難しさ(挑戦を出し続ける)・リズム(体験を変えて飽きさせない)・流れ(目標に向かわせる、ヒントも使う)・フック(前の面との違い)【一説】同上
- **1 面に 1 つのアイデア**: 「決まった最初の 1 手で爆発させる」「とにかく特殊ピースを量産する」など、面ごとに言える狙いを持たせる【一説】Playrix 講演
- **新要素の導入は序盤に速く、後はゆっくり**。新要素を出したら 1〜2 面はそれだけで遊ばせる【一説】同上
- **邪魔なもの(ブロッカー)には役目を決める**: 進行を遅らせる / 勝ちを止める / 難しくする、のどれかを担わせる(RPG の敵の役割を借りた)【一説】GDC 2020 King・Lucien Chen(報道による)
- 自動生成するなら「この配置では必ずこのギミックを使う」ルールを持たせ、既存の面から作った難度の指標で採点する【一説】CEDEC2026「レベル職人に依存しない！ギミックを活かしたパズルゲームのレベル自動生成」
- **解き味**: 試行錯誤が続いた末に一気に解ける面ほど面白い。1 手ごとに正解が見える面は感情の波が小さい【一説】CEDEC2016 大野功二「コントラストで考えるゲームデザイン・レベルデザイン」

### 物理マージの攻め方
- 大きい物を隅に寄せ、小さい物ほど手前に段々に並べる(整地)。合体の順番を先に作っておく【一説】電ファミニコゲーマー「ランカーが『スイカゲーム』を完全解説」(2023-10-31、見出しの「整地」「時差置き」)
- 合体の反動で他の玉が容器の外へ飛ぶことがある。事故も含めて遊び【一説】Wikipedia「Suika Game」
- 自動で合体する型は「溜め」ができない。合体の引き金をプレイヤーに渡すと、並べて溜めて一気に連鎖させる戦略が生まれる【実測】非公開の作品(物理 × 合体の引き金を入力に)
- 「いま押すと何連鎖」を常に見せると、物理のあいまいさの中でも読める。予測と実際が一致することを bot の配置で確かめた【実測】同上

## 6. よく使う UI

- **配置**: 盤面が中央、NEXT は右か上、ホールドは左。スコア・レベル・消した数は盤面の脇に小さく。プレイ中に目を動かさない【定説】tetris.wiki「Tetris Guideline」(NEXT の位置)
- **色と形**: テトリス系は形ごとに色が決まっている(I 水色、O 黄など)【定説】ガイドライン。うちの作品では色だけに頼らず、形・模様・明暗でも分ける。既定の配色を見分けやすい組に変え、色の設定も置いた【実測】非公開の作品(色覚の多様性対応)
- **ゴーストは枠線で**: 半透明のピースで落ちる先を出したら、本物と紛らわしかった。点線の枠にした【実測】非公開の作品
- **連鎖は数字を大きく、音を上げる**: 連鎖・連爆のたびに音程を半音ずつ上げると、数を見なくても伸びが分かる【実測】おばけ提灯(連爆の音階)/ 非公開の作品(連鎖で半音階)
- **危ないことを知らせる**: 積みが上に近づいたら、盤面のふちの色や BGM の重ねで知らせる。対戦は届く予定のおじゃまの量を盤面の上に出す(相殺できる猶予が見える)。
- **スマホの操作**
  - 落ち物: 盤面を左右にドラッグで移動、タップで回転、下フリックでハードドロップ、画面下に ◀ ▶ ⟳ ▼ ⤓ のボタンも置く(指の太さで誤操作するので両方)【実測】非公開の作品(公開デモあり)
  - 物理マージ: 押さずにマウスを動かすだけで落とす位置が付いてくるようにした(押しながら動かす操作は不評)。タッチは指の位置で狙い、離して落とす【実測】同上
  - 3 マッチ: スワイプで入れ替え。タップ 2 回(選んで隣を押す)も受ける。
  - 入力リスナーを `window` だけに付けない【実測】雛形 AGENTS.md(Galaxtris の itch.io × iPhone)
- **リザルト**: 点・最大連鎖・消した数・ハイスコア更新の印。「もう一度」は 1 タップで最初の位置に。

## 9. うちの作品での実例と、踏んだ罠

### Galaxtris(tetrishoot、パズル × 全方向 STG、2026-09)
- 公開 https://mukkii.itch.io/galaxtiris 。落ち物とシューティングのかけ合わせ。itch.io の iPhone だけ移動もショットも効かない問題を数日かけて潰し、実機ノート 1,565 行が雛形の `docs/knowledge/` の元になった【実測】
- 粒 11,000 個を `splice` で消して 147ms/フレーム → 1 パスの詰め直しで 0.5ms。列消しの下詰めも同じく 1 パスで書く【実測】雛形 §6-1
- BGM を `setInterval` で鳴らすとテンポが乱れた(70〜171ms)。音の時計で先読み予約にして 125.0ms ±0.0ms。拍で消える落ち物では致命的なので最初から音の時計で【実測】雛形 §6-2
- 動画 1 本を全配布先に流用する公開キットの最初の作品【実測】`promotion.md`

### 非公開の作品(音楽同期の落ち物 → 物理マージ × リズム、2026-09〜10)
- 1 本目は 2×2 の塊を積み、同色の正方形を拍で流れるバーがまとめて回収する型。2 本目で物理で積んで合体する型に作り直した。
- 合体で 2 個分の幅が 1 個に縮み、すき間で連鎖が切れた → 次の段の仲間側に寄せて生む(§3)【実測】`game-design.md` §7
- 自動合体をやめ、合体の引き金を入力にしたら「溜め」の戦略が生まれた。回復の速さ(2 拍に 1 回)とくっつき判定(1.25 倍)の 2 つのつまみで「考えると 2〜3.5 分で達成、適当だと 47 秒であふれる」に合わせた。つまみを逆に振ると「15 秒に 1 個最大ができる(易しすぎ)」「考えても 54 秒であふれる(難しすぎ)」【実測】
- 自動テストで曲の時計を差し替える時は、曲の開始処理より**後**に差し替える(先だと上書きされて時間が止まる)【実測】HANDOFF
- 着地予測は半透明より点線枠、物理マージの狙いは押さずにホバーで、色覚の設定、を実際のフィードバックで直した(§6)【実測】

### おばけ提灯(ミサイルコマンド系、2026-10)から持ち込めること
- 連鎖を敵どうしにまで広げたら「どこに当てても列ごと消えて何もしなくても勝てる」になった。連鎖はプレイヤーが置いた物の間だけに【実測】`genres/shmup.md` §9。3 マッチの自動カスケードが強すぎる時も同じ見方で絞る。
