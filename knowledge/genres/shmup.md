# 2D シューティング(縦・横 STG、弾幕、インベーダー系、ミサイルコマンド系)

使い方: シューティングを作る前に 1 回通して読む。数値は「つまみ候補」として `src/tuning.ts` に入れ、F2 で人が直す前提の初期値。最終更新: 2026-10-12。
確かさの印: 【実測】うちの作品で確かめた /【定説】複数の出典が一致 /【一説】1 出典だけ(または出典がプレイヤーの経験談)。印の無い数値は、このファイルが置いた仮の値。
用語: 自機 = プレイヤーの機体。雑魚(ポップコーン) = 一撃で落ちる小さな敵。ボム = 画面の敵弾を消す回数制の切り札。エクステンド = 残機が 1 増えること。

## 1. 芯と、1 日で作るパイロットの最小構成

### 芯(これがあればシューティングと感じる)
- **撃つ手応え**: 押した瞬間に太く速いショットが出て、当たった敵が光り、大きく爆発する。【定説】Boghog's bullet hell shmup 101(以下 Boghog)/ 桜井政博「シューティングゲームのゲームデザイン」
- **避ける読み**: 敵弾の軌道を読み、少しだけ動いて抜ける。弾は「読める」ことが前提で、速さより数と並びで難しくする。【定説】Boghog / Bright, Slow, and Deadly
- **画面の取り合い**: 早く倒せば画面がきれいなまま次の波を迎え、遅れると弾が溜まって追い込まれる。【一説】Boghog「Dynamic Design」
- **近いほど強い・危ない**: 敵に寄るほど火力が上がり、被弾も増える。距離がそのまま判断になる。【定説】桜井政博(ダライアスの例)/ Boghog「Shot Limit」(画面内の自弾数の上限で、近いほど連射が速くなる)
- **点と残機**: 稼ぎ(危ないことをすると点が増える)と生き残りがぶつかる。【定説】Boghog「Scoring Systems」/ CEDEC2016 大野功二「コントラストで考えるゲームデザイン・レベルデザイン」

### 1 日パイロットの最小構成(この順で作る)
1. 自機: 8 方向移動(斜めは正規化)、慣性なし、自動連射。画面外に出ない。
2. 敵 3 種: 直進する雑魚 / 止まって自機狙い弾を撃つ砲台 / 硬めの中型(画面上部に居座る)。
3. 出現表 1 本(60〜90 秒)を時刻で書く(§3)。最後にボス 1 体(体力ゲージ + 攻撃 2 段階)。
4. 当たり判定は円だけ。自機の判定は見た目より小さく、中心に小さな点を描く。
5. 残機 3、被弾で敵弾を全消し + 2 秒の無敵。ボム 2 発(押すと敵弾全消し + 無敵 1.5 秒)。
6. スコア・ハイスコア(`core/save`)。リザルトで「もう一度」が 1 タップ。
7. `?auto=1` で避けながら撃つ bot、`?seed=` で再現(`core/rng`・`core/replay`)。
- 後回しでよいもの: パワーアップの段階、ランク、複数ステージ、スクロール背景の作り込み、横スクロールの地形当たり。

## 2. よく使うゲームシステムとゲームフロー

- **フロー**: タイトル → ステージ(道中 → 中ボス → 道中 → ボス)→ リザルト(得点・倒した率・最大倍率)→ 次のステージ or タイトル。1 面 2〜4 分が目安。【一説】東方の攻略 wiki は「基本は全 6 面、各面の最後にボス」と説明(wikiwiki.jp/thk/Lesson)。パイロットは 1 面で十分。
- **残機制**: 初期残機 + エクステンド 1〜2 回 + 1UP アイテム、というように厳しめに配るのが CAVE 系の定石。1 回のミスが重いので、全部の攻撃が練習で避けられる作りにする。体力ゲージ制は「ゆるい設計になりがち」なので避けられがちだが、CAVE にも成功例がある(『ぐわんげ』『デススマイルズ』『赤い刀』)。【一説】Boghog「Lives, Bombs and Recovery」
- **被弾後**: 敵弾を全部消す → 数秒の無敵。連続死を防ぐため無敵は気前よく。【一説】Boghog
- **ボム**: 守り(危ない時に押す)と攻め(ボスを早く削る)の両方に使える資源。**被弾から数フレーム以内のボムで被弾を取り消す**(喰らいボム)と理不尽さが減る。【定説】Boghog / 東方攻略 wiki「喰らいボム」
- **ボムの支給**: 死ぬとボム数を初期値に戻す作りでは、ボムを抱えたまま死ぬと損(「抱え落ち」)。初心者は抱え落ちしやすいので、ボムを押しやすい操作にする。【一説】東方攻略 wiki
- **パワーアップ**: 見た目と弾数は派手に増やし、実際の火力は少しずつ(1 段で ×1.1 程度)しか上げない。10 段目が 10 倍強いと調整が壊れる。【一説】Boghog「Power Ups」
- **低速移動(フォーカス)**: ボタンを押す間だけ遅く・集中ショット。速さは通常の 2/3 が中間。【一説】Boghog。東方は低速時に当たり判定の点が見える。【一説】東方攻略 wiki
- **スコア倍率**: 連続撃破で倍率が上がり、途切れると戻る。「直線的(取りこぼしの罰が小さい)」と「指数的(倍率・まとめ払い。罰が大きい)」を混ぜ、倍率には上限を付けて伸び過ぎを止める。【一説】Boghog「Linear vs Exponential」
- **攻めの稼ぎ / 守りの稼ぎ**: 時間切れで倍率が落ちる型は止まると罰(怒首領蜂)、自分から取りに行く型は止まっても罰なし(ギガウイング)。パイロットは後者が作りやすい。【一説】Boghog
- **コンティニュー**: その場復活 or 面の最初から。点を 0 に戻すと記録の意味が保てる(おばけ提灯は「その日のはじめから、得点 0」)。【実測】
- **残機を「挑戦の目標」に変える**: 無限コンティニューにして、少ないミスでのクリアに印を付ける。弾幕の 1 コイン(ノーコンティニュー)クリア文化と同じ形。【一説】GMTK「Are Lives Outdated Game Design?」
- **ランク(動的難易度)**: 上手いほど敵弾が速く・多く・硬くなる隠しの値。『バトルガレッガ』はパワーアップ・アイテム取得・死なずに進むことで上がり、ミスで下がる。敵の体力は基礎の約 1〜3 倍に伸び、新しく出る敵にだけ効く。【定説】Shmups Wiki「Battle Garegga / Advanced Rank」/ Giant Bomb「Dynamic Difficulty」
  - パイロットでの代わり: 緊張の波を「溜める → 山を保つ → 引く → 休む」の 4 段で回す(Left 4 Dead の AI Director)。上手さで敵数を増減するより、休みを必ず入れる方が安全。【一説】CEDEC2017「人工知能(メタAI)を用いたゲームデザインの変革」
  - 隠しのランクは「なぜ急に難しくなったか」が見えない。入れるなら画面に出す(『怒首領蜂大復活 BL』は目盛りを表示)。【一説】Giant Bomb

## 3. よく使うデータ構造(この雛形での書き方)

雛形の決まり: ゲームの中身は `src/game/logic.ts` の `step(state, input, cfg)` で **1/60 秒(TICK)ずつ**進め、Phaser・DOM・`Math.random` を使わない。描画は state を読むだけ。`core/fixedstep.ts` が画面の Hz に関係なく step を回す。

### 入力(人・bot・記録の再生が同じ口を通る)
```ts
export interface Input { dx: number; dy: number; fire: boolean; bomb: boolean; focus: boolean }
// encodeInput: 'L','R','U','D','F','B','S' の組み合わせ 1 文字ずつ(core/replay.ts で ?replay= に載る)
```
- スマホの相対タッチは「この tick に動かしたい量」を dx/dy に入れて中身に渡す。座標は入口で丸める(記録の再生がずれる罠)。【実測】おばけ提灯 2026-10-06

### 弾と敵は固定長の配列で使い回す(object pool)
- 生成と破棄を毎回やらず、最初に N 個作って「使用中」フラグで回す。満杯の時の扱いを決めておく: 演出の粒は「作らない」、敵弾は「上限に当たらない大きさにする」、ボスは「必ず空ける」。【定説】Game Programming Patterns「Object Pool」/ 雛形 `docs/knowledge/web-game-rules.md` §6-1
- 寿命切れを 1 件ずつ `splice` すると O(n²)。1 パスで詰め直す。粒 11,000 個で 147ms → 0.5ms。【実測】Galaxtris(雛形 §6-1)
```ts
interface Bullet { alive: boolean; x: number; y: number; vx: number; vy: number; r: number; kind: number }
const POOL = 1024; // つまみにはしない。画面内の最大弾数の 2 倍程度
```
- 使い回す時は全部の値を初期化する(前の弾の値が残ると、ほぼ正しく見えて気づけない)。【一説】Game Programming Patterns

### 出現表(ステージ定義)は時刻で書く
- 縦スクロールでも「スクロール位置」より「開始からの秒」で書く方が、bot の再現・調整パネルでの早送り・面ごとの切り出しが楽。背景の速さが一定ならどちらも同じ。
- 1 行 = 1 つの波(編隊)。敵の種類・数・間隔・入る位置・動き・撃ち方を名前で指す。
```ts
// src/game/stage1.ts(中身側。描画と無関係)
export const STAGE1: Wave[] = [
  { t: 2.0,  enemy: 'popcorn', count: 5, every: 0.25, from: { x: 0.2, y: -0.05 }, path: 'dive',   shot: null },
  { t: 5.0,  enemy: 'popcorn', count: 5, every: 0.25, from: { x: 0.8, y: -0.05 }, path: 'dive',   shot: null },
  { t: 8.0,  enemy: 'turret',  count: 1,              from: { x: 0.5, y: -0.05 }, path: 'stop25', shot: 'aim3' },
  { t: 14.0, enemy: 'midboss', count: 1,              from: { x: 0.5, y: -0.1  }, path: 'hover',  shot: 'ring16', waitClear: true },
  // ... t: 75 で boss。waitClear: その敵が消えるまで時刻を止める
];
// x, y は画面幅・高さに対する割合(0〜1)。縦横を変えても表が使える
```
- 「前の波が全滅したら次」より時刻で重ねる方が流れが出る(§5 の重ね)。中ボス・ボスだけ `waitClear` で止める。
- 面のデータに「手本(何秒にどこへ動くか)」と目標点を持たせ、描画なしで手本が届くかを CI で回すと、ルール変更で面が壊れたのがすぐ分かる。【実測】おばけ提灯 `tools/stage.mjs`

### 弾のパターンは「発射のしかた」をデータで書く(BulletML の考え方)
- BulletML は弾幕を XML で書く言語。「撃つ(fire)・待つ(wait)・繰り返す(repeat)・向きと速さを変える(changeDirection / changeSpeed)・弾が弾を撃つ」を組み合わせる。【一説】ABA Games「BulletML」
- パイロットでは XML まで要らない。発射を 1 つの関数にまとめ、引数で種類を作る:
```ts
// way: 同時に撃つ列数 / spread: 列の開き(度) / aim: 自機狙いか / speed: px/秒 / rot: 撃つたびに回す角度
type Shot = { way: number; spread: number; aim: boolean; speed: number; every: number; burst: number; rot?: number };
export const SHOTS: Record<string, Shot> = {
  aim1:   { way: 1,  spread: 0,   aim: true,  speed: 150, every: 1.2, burst: 1 },
  aim3:   { way: 3,  spread: 20,  aim: true,  speed: 140, every: 1.5, burst: 3 }, // 奇数弾
  even2:  { way: 2,  spread: 12,  aim: true,  speed: 160, every: 1.0, burst: 1 }, // 偶数弾(止まっていれば当たらない)
  ring16: { way: 16, spread: 360, aim: false, speed: 110, every: 0.8, burst: 1, rot: 11.25 },
};
```
- 弾の向きは発射の瞬間に決め、以後はまっすぐ等速が基本。曲がる弾・加速する弾は残像を付ける。【一説】Boghog「Bullet Visibility」

### 当たり判定
- **全部円**: `(dx*dx + dy*dy) < (r1 + r2)²`(平方根を取らない)。ナイフ形の弾も判定は円にすることが多く、横から当たると「当たって見えないのに死ぬ」。細長い弾は円を 2〜3 個並べる。【一説】東方攻略 wiki「当たり判定を知る」
- **組み合わせを減らす**: 自機 1 × 敵弾 N は総当たりで足りる(N=1000 でも 1000 回)。重いのは自弾 × 敵(例 60 × 40 = 2400 回)。敵が 50 を超えたら、画面を 64px 角の格子に分け、同じマスと隣のマスだけ調べる(空間分割)。【定説】Game Programming Patterns「Spatial Partition」/ 雛形 §6-4(重い判定の前に外接矩形)
- 判定の関数に演出を混ぜない(画面外の敵から粒が出続けた。最大 768 個/フレーム)。【実測】Galaxtris(雛形 §6-4)
- 速い弾が薄い敵をすり抜ける時は、1 tick の移動距離が判定の直径を超えていないか見る。超えるなら弾を細かく刻んで判定する。

### 固定刻みの更新
- 速度は「px/秒」で持ち、step の中で `* TICK` する。画面が 120Hz でも同じ結果になる。【実測】雛形 `logic.ts` の決まり
- 速さの単位を作品の中で 1 つに揃える(フレーム単位と秒単位を混ぜない)。【一説】桜井政博「速度の単位」

## 4. よく使うゲームバランスの指針

| 項目 | 初期値(つまみ候補) | 根拠・印 |
|---|---|---|
| 自機の当たり判定 | 半径 2〜3px(絵 24〜32px の中心) | 見た目より小さく・真ん中に置くのは【定説】(Boghog / 東方攻略 wiki / 学生の制作報告)。px は仮 |
| 敵弾の当たり判定 | 絵の半径の 60〜70% | 大弾の判定は見た目より小さい【一説】東方攻略 wiki。% は仮 |
| 自機の速さ | 300px/秒(幅 480 の画面を約 1.6 秒で横断) | 雛形 `player.speed` の既定。狭い画面ほど遅め・細いショット、広い画面ほど速め・広いショット【一説】Boghog |
| 低速移動 | 通常の 0.66 倍 | 【一説】Boghog |
| 自機のショット | 700〜900px/秒、太く長い絵 | 自弾は速く、絵を長くするほど速く見える【一説】Boghog |
| 敵弾の速さ | 100〜220px/秒 | 敵弾は遅くする。自弾と同じ速さから半分にしたら、避けて撃ち込む遊びに変わった【一説】Bright, Slow, and Deadly。数値は仮 |
| 被弾後の無敵 | 2.0〜3.0 秒 + 敵弾全消し | 「数秒」【一説】Boghog |
| 喰らいボムの猶予 | 4〜8 tick | 「数フレーム」【定説】Boghog / 東方攻略 wiki |
| ボムの無敵 | 1.5〜2.5 秒 | 仮 |
| 画面内の自弾上限 | 1 発(インベーダー型)〜無制限 | ギャラガは 2 発。上限が低いほど寄って撃つ遊びになる【一説】Boghog |

- **慣性は付けない**。少しの加速でも上手い人には分かる。動きが「滑らかでない」と感じたら、慣性ではなく見た目(ショットの太さ、残像、機体の傾き)を足す。斜めも同じ速さに正規化する。【一説】Boghog
- **プレイヤーにほんの少し有利に**: 自弾の判定と敵の被弾判定は大きく、敵に重なった真上からでも当たるようにする。小さなミスは許し、大きなミスだけ罰する。【一説】Boghog
- **見た目と計算を分ける**: 揺れ・反動の演出は派手にしても、実際の狙いや判定は演出に引きずらせない。【一説】テトラポッド葉山「GDC2026 報告会 ゲームデザイン」(Battlefield 6 の例)
- **抜け道(レーン)**: 濃い弾幕は「何本かの通り道」の集まりとして作る。道ごとに安全さと火力の得失を変える。画面の大きな塊を丸ごと塞いで「外で待つだけ」にするのは失敗。【一説】Boghog「Lanes」
- **安全地帯**: 撃ち込める安全な場所を「わざと」用意するのはご褒美として効く。偶然できた安全地帯(何もしなくても避けられる場所)は bot の idle / 一点に留まる bot で探して潰す。【実測】おばけ提灯(家の前で待つだけが最強だった)
- **同時に撃つ敵の数を絞る**: 敵が 10 体いても、撃ってよい権利(トークン)を 2〜4 枚だけ配り、撃ち終わったら返させる。見た目の迫力と実際の難しさを切り離せ、難易度は枚数で変えられる。【定説】GDC「Embracing Push Forward Combat in DOOM」/ GDC「Authored vs. Systemic … Combat AI in Uncharted 4」/ CEDEC2023『FINAL FANTASY XVI』コンバットデザイン講演
- **撃つ前に予告する**: 構える → 光る → 撃つ、の段階を見せる。予告なしの弾は「ただのダメージ」に感じる。【一説】GDC「Embracing Push Forward Combat in DOOM」
- **ランダムは避けの中だけ**: ばらまき弾(ランダム)は「気合いで避けるしかない」。固定弾・自機狙いと混ぜ、ランダムだけで面を作らない。【定説】Boghog「Pattern Types」/ 東方攻略 wiki
- **難易度曲線**: 敵の種類を 1 つずつ足していく(最初は 2 種、慣れたら次)。ウェーブを重ねるごとに弾を増やすと、同じ操作に緊張が生まれる。【定説】GMTK の DOOM Eternal 戦闘分析(https://www.youtube.com/watch?v=I9ZsFT_eqXY)/ CEDEC2026『スペルトナエル』講演
- **稼ぎと安全のぶつかり**: 近いほど火力・点が上がる(ダライアスは距離で連射が変わる)。武器を複数にするなら「全部の敵に最適」な武器を作らない。【定説】桜井政博「シューティングゲームのゲームデザイン」/ CEDEC2016 大野功二
- **点の仕組みは段階を付ける**: 最初は単純な目標だけ見せ、細かい稼ぎは後から気づかせる。大事な点の要素ほど目立たせる。【一説】Boghog「Depth vs Clarity」
- **bot で測る**(雛形 `src/game/bots.ts` + `tools/sim.mjs`): idle(何もしない)/ random / 避けて撃つ think / think の 0.6 秒遅れ を並べ、生存時間・被弾数・点を見る。
  - idle が長く生きる → 敵弾が自機に届いていない。think と遅れ版の差が大きい → 反射神経だけのゲーム。【実測】おばけ提灯(0.6 秒遅れで 7 割 → 3 割)
  - bot の成績が急に崩れたら、まずゲームの中身の不具合を疑う。【実測】おばけ提灯(雛形 §9-10)
- **つまみ候補の一覧**(`src/tuning.ts` に入れる): `player.speed` `player.focusRate` `player.hitR` `shot.speed` `shot.every` `enemyBullet.speedMul` `enemyBullet.hitRate`(絵に対する判定の割合)`enemy.hpMul` `spawn.timeMul`(出現表の時刻を詰める倍率)`death.invuln` `bomb.count` `bomb.invuln` `deathbomb.window` `score.multCap` `extend.score` `audio.sfx` `audio.bgm`。曖昧な注文(「もっと気持ちよく」)は、このどれを何から何へ動かすかに直して返す。

## 5. よく使う攻略パターン・敵の組み合わせ・レベルデザイン

### 敵弾の型(避け方とセットで覚える)
- **自機狙い奇数弾**(1・3・5 列): 真ん中の列が撃った瞬間の自機の位置を狙う。止まると当たり、少し横へ動けば当たらない(「ちょん避け」)。大きく動くと弾がばらけて読みにくくなる。【定説】東方攻略 wiki / Boghog「Aimed」
- **自機狙い偶数弾**(2・4 列): 自機の両脇を通る。止まっていれば当たらない「見かけ倒し」。【一説】東方攻略 wiki
- **切り返し**: ちょん避けを続けると画面端に追い込まれる。真ん中と端の間あたりで、一気に斜め上へ大きく動いて弾をばらけさせ、その隙間から反対へ戻る。設計側は「切り返す余地が残る弾の間隔」を作る。【一説】東方攻略 wiki
- **固定弾**: 自機に関係なく毎回同じ。覚えれば確実に避けられる。「美しい模様」を見せる場所。【定説】Boghog「Static」/ 東方攻略 wiki
- **ばらまき**: ランダム。新鮮さを出すが不公平になりやすい。【定説】同上
- **重ねる**: 固定弾(長い弾)で動ける場所を狭め、自機狙い(太い丸弾)で動かす。3 つの型の組み合わせで弾幕の大半ができる。【一説】Boghog

### 敵の役割と組み合わせ(エネミーセット)
- 役割は 3 つ: **圧をかける**(自機狙いで動かす)/ **場所を塞ぐ**(固定弾で画面を区切る)/ **正面から挑む**(硬い中型・中ボスの濃い弾幕)。波ごとに組み合わせる。【一説】Boghog「Enemy Roles」
- 倒し方 3 通りを決めておく: すぐ倒された時(最低 1 回は撃たせるか)/ 普通 / 倒すのが遅れた時(居座って追い込むか、去るか)。体力を低く保ちつつ必ず 1 回撃たせたいなら、最初の 1 発までは無敵にする。【一説】Boghog「Dynamic Design」
- 雑魚の体力は役目に要る分だけ。**放っておいて画面外へ逃がす方が得**になる敵を作らない(硬い敵がゆっくり降りてくると、その下にいるのが危険になる)。【一説】Boghog
- 敵の種類ごとにシルエットと色を揃え、同じ種類は近くにまとめて出す。一目で「何をすべきか」が分かる。【一説】GDC「Bridging the Gap Between UX Principles and Game Design」
- **硬い敵 2 体を同時に出さない**。少しずらして 1 体ずつ出すと「次はあれ」という道筋ができる。【一説】Boghog

### 雑魚の編隊
- 縦一列で降りる / 横一列で横切る / V 字 / 画面端から弧を描いて入る(ギャラガ型)/ インベーダー型(横に渡って端で 1 段下がる。数が減ると速くなる)。
- インベーダーの「減るほど速くなる」は、意図した仕様ではなく処理の軽くなった結果だったという分析もある。【一説】Red Hot Cyber の分析記事(2025)。仕様として使うなら「最後の 1 体は速い」(おばけ提灯は 1.8 倍)。【実測】
- 編隊を全部倒したらボーナス(おばけ提灯: 40 × 数 × 刻)。【実測】

### 道中の配置
- **Toaplan 型**: 画面を 5〜7 本のレーンに分け(画面の両端にはレーンを置かない)、次の敵を前の敵と反対側に出す。左右に振られるリズムが流れを作る。【一説】Boghog「The Toaplan Pattern」
- **重ね**: 主役の波(Toaplan 型)が終わる前に次を出し、間に雑魚をまぶす。早く倒せばきれいな画面で次を迎え、遅れると追い込まれる。【一説】Boghog「Layered Design」
- ジグザグに動かす配置は止まらせないので流れが出る。地上の砲台を縦に積むと往復を強いて止まる。敵を画面の端の近くに置くと罠になる。【一説】Boghog
- プレイヤーは画面の縦の真ん中あたりに居たがり、硬い敵が撃つ前に寄って撃ち込み、撃たれたら下がる。斜めの弾避けや画面の片側での上下移動は嫌がる。この癖に沿って置く。【一説】Boghog「Player Behaviours」
- **緩急**: ずっと最大の濃さだと全部が同じに感じて疲れる。濃い所の前後に薄い所。同じ敵を続けて 2〜3 回出すと覚えやすい(出し過ぎない)。中ボス・背景の出来事を目印に置く。【一説】Boghog「Pacing」/ 休みを必ず入れる【一説】CEDEC2017 メタAI 講演
- **細かい親切**: 地上の弱い敵は自機が真上・すぐ近くにいる時は撃たない(弾封じ)。画面のすぐ上の帯では敵に当たらない(見えない敵を倒させない)。【一説】Boghog「Polish Effects & Minor Mechanics」

### 中ボス・ボス
- ボスは 2〜4 段階。体力ゲージの区切りで攻撃を替え、段階が進むほど型を重ねる(固定弾だけ → 固定 + 自機狙い → 3 つ全部)。区切りで敵弾を消して一息つかせる。
- 各段階に時間切れ(30〜60 秒)を付け、遅くても進む(パイロットで詰まらない)。仮
- ボムを使えばボスに密着して撃ち込める。ボムの無敵が切れる前に下がれるよう、無敵の終わりを音か点滅で知らせる。【一説】東方攻略 wiki

### ミサイルコマンド系(近縁。先読み迎撃)
- 芯は 3 つ: **弾の飛行時間**(撃ってから着くまでの間に敵が進む = 先読み)/ **広がって縮む爆発**(時間の窓。大きさ・速さは常に一定)/ **読める軌跡**(まっすぐ・一定速)。1 行の解釈(「先を読んで置く」)だけで作ると面白さを落とす。【実測】おばけ提灯 2026-10-06
- 弾は守る基地にあり、基地も守る対象(撃つ場所の選択)。使い切ったら何もできない時間を作らず、時間で少しずつ戻す。【実測】おばけ提灯 2026-10-08
- 敵の出口が見えて届く所にあると、出口で待ち伏せするだけになる。画面の外から入らせる。【実測】おばけ提灯
- 原作は「補給線(鉄道)」を入れる案を捨てた。上手い人ほど線の先の遠い都市を見捨てたから。上部の状態表示も、画面から目が離れるので捨てた。【一説】arcade-history.com「Missile Command」
- 説明のサイン(残り時間の輪・数字・警告色)を足すほど「分からない・かっこ悪い」と言われた。大きさと速さを一定にして読ませる。【実測】おばけ提灯

## 6. よく使う UI

- **HUD**: スコアとハイスコアは上(左にスコア、右にハイスコアが多い)。残機とボムは下の隅か上の隅に、数字ではなくアイコンを並べる。プレイ中に目を動かさなくて済む位置と大きさにする。原作のミサイルコマンドは画面外の表示を「目が離れる」として捨てた。【一説】arcade-history.com
- **ボスの体力ゲージ**: 画面の一番上に横長。段階の区切りに目盛り。ボス名は出す時だけ。
- **当たり判定の点**: 自機の中心に小さく明るい点。低速移動の間だけ出す型もある(東方)。【一説】東方攻略 wiki
- **敵弾を一番手前に描く**。小さく速い弾ほど上に。自機・自弾・アイテム・爆発の後ろに敵弾が隠れると理不尽な死になる。【定説】Boghog / Bright, Slow, and Deadly
- **敵弾の色**: 明るい芯と暗いふちを隣り合わせる(明暗の差)。背景は中間の明るさで低い対比に。赤・ピンク・紫は爆発や金色のアイテムと混ざりにくい。点滅や揺れのアニメで目を引く。【定説】Boghog / Bright, Slow, and Deadly(作品の色づかいを無視してでも目立たせてよい)
- **自機の位置は弾の流れで分かる**: プレイヤーは自機を見ず、自分のショットの束と機体の形で位置を推し量る。太く速いショットは手応えにも視認性にも効く。【一説】Boghog
- **縦画面の余白**: 横長の画面に縦の遊び場を置く時は、左右の余白にスコア・残機・ボム・倍率を寄せ、遊び場の中を空ける。スマホ縦持ちでは遊び場を画面いっぱいにして HUD を上下の帯に。
- **音で知らせる**: 敵の出現・ボスの段階・残機が最後になった、を効果音や声でも出す。見えにくい人にも、見えている人にも状況が分かりやすくなる。【一説】CEDEC2026 アクセシビリティ講演(CEDiL 3266)
- **画面揺れ・強い点滅を切れるようにする**。爆発の多いジャンルなので、設定に 1 つ置く。【一説】GMTK のアクセシビリティ動画(https://www.youtube.com/watch?v=RWQcuBigOj0)
- **スマホの操作**:
  - **相対タッチ**(指を置いた所からの動いた分だけ自機が動く)が主流。指が自機を隠さない。感度(1.0〜2.0 倍)をつまみに。【一説】TouchArcade フォーラム「Preferred control method for shmup」/ nineoverten「design patterns of shmups on iPhone」(2009)。どちらも経験談
  - **自動連射**にして指は移動だけに使う。移動しないと撃てない作りは嫌われた。【一説】同上
  - ボムは画面の隅のボタン(本物の DOM の `<button>` を最後の砦に)。2 本指タップでも可。
  - itch.io の iPhone 埋め込みで「タイトルは進むのに、移動もショットも効かない」が起きた。原因は Pointer Events の `pointercancel` が同じフレームでショットを降ろしていたこと。タッチは Touch Events を主にし、押した瞬間を 1 フレーム保持して直した。【実測】Galaxtris(雛形 `docs/knowledge/itch-mobile.md`)
  - 入力リスナーを `window` だけに付けない(雛形 AGENTS.md)。【実測】

### 爆発・ショット音の作り方
- **ZzFX**(https://github.com/KilledByAPixel/ZzFX、MIT)— 1 行の数値配列で効果音を鳴らす極小ライブラリ。配列をコードに直書きでき、ファイルが要らない。

- 敵の爆発の絵は敵より十分大きく、破片を足す。当たった敵は点滅か揺れで反応させる。【一説】Boghog

## 9. うちの作品での実例と、踏んだ罠

### おばけ提灯(ミサイルコマンド系、2026-10-06〜)
- repo: `mukkii-game/obake-chochin`。公開 https://mukkii-game.github.io/obake-chochin/ 。指を離した所へ提灯を投げ(140px/秒)、着いて 3 秒で弾ける。誘爆は 0.2 秒ずつ。3 日 × 3 刻 = 9 ウェーブ。
- 1 本目は 16 分で公開まで行ったが、Mukkii の判定は「つまらない」。動くか・壊れていないかしか確かめておらず、面白さを測る仕組みが無かった。→ bot を並べて芯を測る型が生まれた(§4)。【実測】`progress/2026-10-06-postmortem-obake-chochin.md`
- 元ネタの芯を 1 行で解釈して「原作の面白さを失いすぎ」と言われた。芯を 3〜5 個の仕組みに分けて作り直した(§5 ミサイルコマンド系)。【実測】
- 名作は「動詞」で混ぜる: ミサイルコマンド = 先を読んで撃つ / ボンバーマン = 並べて誘爆 / ギャラガ = 編隊と輪。【実測】`knowledge/game-design.md` §3
- 敵どうしの連鎖を入れたら「どこに当てても列ごと消えて何もしなくても勝てる」。連鎖はプレイヤーが置いた物の間だけに。【実測】
- 敵の通り道の線を出したら、先読みの答えになって楽しさが消えた。【実測】

- 記録の再生がずれた: 記録は整数に丸めるのに本番は小数座標だった / bot がゲームと同じ乱数を使っていた。入口で丸め、bot に別の Rng。【実測】
