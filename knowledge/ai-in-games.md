# ゲームに AI を入れる時の選び方(会話 LLM・判定 Clef・ルール)

共通の中継 `mukkii-game/game-llm`(https://game-llm.mucky-totoro.workers.dev)で、どの作品も同じ口から使える。使い方は game-llm の README。

## まず「文章が要るか」で分ける
| やりたいこと | 使うもの | 理由 |
|---|---|---|
| キャラが自由にしゃべる・文章を作る | **会話 LLM**(`/api/chat`) | 文章を作れるのはこれだけ。遅い(1〜数秒)・枠を食う |
| 決まった選択肢から選ぶ・分類する・点数を付ける | **判定 Clef**(`/api/decide`) | 文章を作らず確率だけ返すので速く(数十〜数百 ms)安い。結果がそのままゲームの分岐に使える |
| 毎フレーム・絶対に外せない・再現が要る | **ルール(普通のコード)** | 速く、毎回同じ。AI は「決め方を変える時だけ」呼ぶ |

迷ったら: **判定で済むなら判定、文章が要る所だけ会話 LLM、残りはルール。** 3 つは組み合わせる。

## プレイ中(ゲームの中)での Clef の使いどころ
- **会話ゲームの振り分け**: 発言を「質問/感想/ふざけ/話題転換/別れ」に分けてから、ルールか会話 LLM のどちらで返すか決める(全部 LLM にしないので速く・安く・壊れにくい)
- **感情・熱量の判定**: 発言の熱量や好き嫌いを score で取り、隠しパラメータ(好感度・テンション)を動かす
- **敵・NPC の作戦選び**: 1 秒に 1 回など「状況が変わった時」だけ「攻める/逃げる/待つ」を選ばせ、細かい動きはコード
- **自由入力の受け付け**: プレイヤーが打った言葉を、ゲームが知っている行動・アイテムのどれかに当てはめる(パーサー代わり)
- **やってはいけない**: 毎フレーム呼ぶ / 結果が無いと進めない作り(失敗時は必ずルールで決める)/ 再生・自動テスト中に呼ぶ

## 開発中(作る側)での Clef の使いどころ
- **bot プレイテスト**: bot の判断だけ Clef、操作はコード。何十回も回して難しさや詰まる所を測る(安いので回数を回せる)
- **画面の確認**: スクリーンショットを渡して「文字が切れている/重なっている/真っ黒」を判定(Clef は画像も読める)
- **大量の仕分け**: 素材・記事・バグ報告・プレイヤーの感想を「使える/使えない」「重要度」で振り分ける
- **会話 LLM の出力の検査**: 会話 LLM の返事が「キャラらしいか」「禁止の話題に触れていないか」を判定で確かめる

## 費用と守り
- 会話も判定も **Workers AI の無料枠(1 日 10,000 Neurons)を分け合う**。超えたらルールに落ちる(請求は来ない)
- 質問と選択肢は **game-llm の `games/<作品>.js` にだけ置く**(ブラウザから受け取らない)
- Clef の土台は Qwen(中国)。動くのは Cloudflare のサーバーで、データは外に出ない。政治的な話題の判定には使わない

## 会話ゲームは「大量のレパートリー + LLM は選んでつなぐ役」(Emmichy の実験 2026-10-07)
- 汎用 LLM に毎回面白さを一から発明させるより、ゲーム専用の台詞・掛け合いを大量に持たせる方が有望。
- 単発の反応だけでなく、2〜5 往復の小さな流れ、前振り → 回収 → オチ、二人だけの合言葉、終わりでの回収を、タグ・条件・再使用の待ち時間(cooldown)付きで持つ。
- 探すのはまず決まった規則(タグと点数と履歴)で。意味で探す仕組み(embedding / RAG)は要るまで入れない。
- 目標は「同じ人が 10 回遊んでも、良い会話の流れがかぶりにくい」。
- LLM の役目は発明ではなく、選ぶ・つなぐ・少し言い換える・想定外の入力に応じる。
