# 作品の最低限(雛形から始めなかった作品を、後から管理に乗せる)

雛形 `web-app-template` から作った作品は全部入りなので、ここは要らない。
雛形より前に始めた作品・なんとなく始めて本格化した作品・Codex など別の AI が始めた作品に、**この最低限だけ**を後から入れる。
入れると: 毎朝の作品台帳(ai-ops)が状態と次の一手を読め、毎晩の回収が気づきを拾え、どの AI が引き継いでも同じ決まりで動く。

台帳は AGENTS.md の `war-room-minimum` の印で判定する(雛形 = 全部入り / 最低限 / 未整備)。

## 入れるもの(4 つ。既にあるものは消さずに足す)

### 1. AGENTS.md の先頭に、この塊をそのまま(Claude も Codex も読む)
```
<!-- war-room-minimum v1: 正本 mukkii-game/Perfect_Dev_Environment/global/work-minimum.md -->
## 最低限の決まり(全作品共通。下の記述と食い違えばこちらが優先)
- 本番は main 1 本。公開は main から出す。作業ブランチは短く切って main へ PR。同じ repo に同時に push する者は 1 つ。
- 始める前に pull。push のたびに HANDOFF.md の「現状」を直す。区切りで「次の一手」「既知の問題」も直す。
- 迷っても止まらず仮決めし、QUESTIONS.md に `- [ ] 何を仮決めしたか / 他の案` で残す(人間が後でまとめて答える)。
- 他の作品でも役立つ気づきは HANDOFF.md の「全体に共有したい気づき」へ(毎晩回収される)。
- 使った素材は CREDITS.md に出典と規約。秘密情報はコミットしない。テストを消さない。
- Mukkii への報告と頼みごとは日本語。
```

### 2. CLAUDE.md(無ければ作る)
1 行目に `@AGENTS.md`。既存の中身は残す。

### 3. HANDOFF.md(無ければ作る。あれば見出しだけ足す)
```
# HANDOFF
## 現状
- (今どこまで動くか・どこで公開しているか・本番のブランチ)
## 次の一手
- (次にやること 1 行目が台帳に載る)
## 既知の問題
## 全体に共有したい気づき
```
古い長い記録がある時は、上にこの 4 見出しを置き、古い記録は下に残す(「以下は整備前の記録」と 1 行)。

### 4. QUESTIONS.md(無ければ作る)
未回答は `- [ ] ` で始める(台帳が数える)。答えが出たら `- [x] `。

## 入れ方
- 作業ブランチで入れて main へ PR → マージ。1 回で済む(10 分)。
- **ブランチが分かれていたら先に main へ集める**(公開用の別ブランチがあると、新しい公開先に古い版が出る。2026-10-13 emmichy)。
- 既存の AGENTS.md と食い違う決まり(「main は触らない」など)は消さずに、HANDOFF の「現状」に「最低限の決まりで上書き」と 1 行書く。
- 公開・Cloudflare の鍵・Issue から Claude を呼ぶ仕組みが要るなら、会議室の Claude に「<作品> を Enable Claude して」と頼む(ai-ops が配る)。
- SNS から遊ばれる作品は、雛形の `src/core/inapp.ts`(アプリ内ブラウザで「ブラウザで開く」を出す。他に依存しない 1 ファイル)を写して起動時に `installInAppBanner()` を呼ぶ。
- 雛形の仕組み(core/・テスト・調整パネル・自動公開キット)まで入れるかは別の判断。作品を本格的に作り直す時だけ。
