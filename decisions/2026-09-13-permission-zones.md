# 決定: AI の権限は「制限」ではなく「3 ゾーン + 確認の仕組み」で扱う

日付: 2026-09-13

## 決めたこと

AI が触れる範囲は狭めない。PC のどこでも触れてよい(Work 的な使い方)。代わりに、場所ごとに「確認の取り方」を変える。

| ゾーン | 対象 | AI の振る舞い |
|---|---|---|
| A 自由 | `E:\`(ゲーム・個人開発)、`G:\マイドライブ` の個人開発フォルダ、作品 repo、開発用スプシ | 確認なしで読み書き・削除 |
| B 確認 | `G:\` の個人の仕事データ、E: 以外のシステム領域、Chrome の仕事ログイン先 | **書き換え・削除の前に必ず人間に許可を取る**。読むのは自由。危険度の高い操作はセッションの前半にまとめて聞く |
| C 社外 | 社外ドライブ(G: 内ショートカット経由)、他社の SaaS | 直接は触らない。成果物を A ゾーンの `outbox/` に置き、人間が許可したら **配達係**(AI でも、定型動作しかしない Python / GAS でもよい)が反映する。配達係は「何をどこへ」の一覧を出して承認を待つ |

## 却下した案

- 社外ドライブのショートカット除去、`E:\ai\` への物理的な限定。ユーザーの意向は「必要なら何でも触ってほしい」なので、遮断ではなく確認で守る。

## 実装で押さえること(11 の次の作業)

- 「B では聞く」を AI の判断だけに任せない。Claude Code の hook(ツール実行前に走るスクリプト)でパスを見て、B・C のパスへの書き込みは自動で止めて人間に聞く形にする。Cowork / Desktop 側の許可設定も同じ境界に合わせる。
- C の配達係は 08(自動化)で作る。最初は「outbox → 指定フォルダへコピー、一覧表示して y/n」の Python 1 本でよい。
- ゾーンの表は topics/11 に置き、月 1 の Routine で「新しく触れるようになった場所」を検出して表に足す。
